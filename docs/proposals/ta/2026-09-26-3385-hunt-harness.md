## Splits and purge
Sessions are NYSE sessions.
- **discovery** 1990-01-02 → 2008-12-31; **validation** 2009-01-02 → 2021-06-28;
- **holdout** `HOLDOUT_BOUNDARY` → an end session frozen in the holdout declaration. It is a **corroboration**
  window, already partly seen (#3384 Finding 5).

**Timeline (construction).** Formation session t; entry session e = t + lag; exit session x = e + h − 1; points
`entry_point`, `exit_point` ∈ {open, close}. Integers lag ≥ 1, h ≥ 1. The hold must have positive duration: with
h = 1 only open → close is allowed. Exit is always at x; there is no late exit or delayed entry.
- **Horizon cap (construction):** lag + h − 1 ≤ 63, so x ≤ t + 63 and every label sits inside the 63-session embargo.
- **Purge:** an observation belongs to split S only if t, e and x all fall in S.
- **Embargo:** formations in the first 63 sessions of validation and of holdout are dropped, not moved.
- **Fitting.** A fitted value is a **literal constant in the spec**. At run time a signal may use only causal
  transforms of data ≤ t. Validation and holdout specs carry constants fitted on discovery only.

**Survivor conditioning** (#3384 Finding 1): every series trading before 2013-06-21 survives to at least that date.
Every spec carries a required `survivor_bias_direction` ∈ {`favours_arm`, `favours_control`, `unknown`} with a
reason, and every validation readout reports the sub-spans before and after 2013-06-21 side by side (descriptive;
selecting one is a new trial).

## A trial
`TrialSpec` is a frozen dataclass. Nested values are tuples or frozen mappings. Canonical JSON: sorted keys, compact
separators, integers as JSON integers, floats as their shortest round-trip `repr` string, non-finite values
refused.
- **`candidate_sha256`** covers what defines the hypothesis and its data: signal id and code hash, sign,
  selection, lag, h, points, constants, weighting, lane, `universe_identity`, `cost_model_id`, `harness_model_id`.
  It excludes `hunt_id`, `family`, `split` and labels, so relabelling cannot make a candidate new.
- **`spec_sha256`** = candidate plus `hunt_id`, `family`, `split`.

| field | content |
| --- | --- |
| `hunt_id`, `family` | e.g. `hunt-1`, `overnight_intraday` |
| `signal_id`, `signal_code_sha256` | see "Signals" |
| `sign` | +1 selects the top of the score, −1 the bottom. It never flips the test: the prediction is always that the selected long book beats the control. `mechanism` and `competing_explanation` are text |
| `selection` | fraction f ∈ (0, 0.5]; count ⌈f · N⌉ of the N scored names, ties at the cut all included and counted |
| `lag`, `h`, `entry_point`, `exit_point` | as "Timeline" |
| `constants` | the fitted literals, passed to the signal |
| `weighting` | `equal` only |
| `lane` | `real_stock_long_x1` only (see "Lanes") |
| `universe_identity` | `validated_ids_sha256`, price-archive identity (incl. its dividend and split tables), `termination_identity` |
| `cost_model_id`, `harness_model_id` | the frozen models |
| `survivor_bias_direction` | as above |

**Binding.** Before computing, `evaluate` recomputes the signal module's hash, the universe identity from the live
archive, and reads the running `COST_MODEL_ID` / `HUNT_HARNESS_MODEL_ID`. Any mismatch with the spec refuses
(`identity_mismatch`) before registration.

**Signals.** `signal(t, view, constants) -> {series_id: score}` in `app/services/hunt_signals/<family>.py`. The
view holds bars ≤ t for the eligible names, **rebased so each series' close on t equals its as-traded close on
t**; a later split cannot change a price level the signal sees.
- A test restricts `hunt_signals` modules to an import allowlist (stdlib `math`/`statistics`/`dataclasses`/
  `typing`, numpy, the view type): no DB driver, reader, file or network I/O, or randomness. The code hash covers
  the module, not the view implementation, the stdlib or numpy.
- A look-ahead probe test drives a signal that indexes past t.
- ⚠ Code-review enforcement, not a sandbox (residual).
- A missing or non-finite score makes the name **unscored** on t (below).

**Eligibility (construction)**, the same for both books, bars ≤ t only (#3384 Input 4). A series is eligible on t
when it is in the admitted set, has a bar on t, and that bar is valid: O, H, L, C finite and > 0; L ≤ min(O, C);
H ≥ max(O, C); volume finite and > 0; H > L. Per formation the harness counts each exclusion reason and the unscored
names.

## Registration: the log comes before the number
New migration (next free number), both tables append-only by trigger (the `sql/264` pattern):
- **`hunt_trials`**: `hunt_trial_id`, `hunt_id`, `family`, `split`, `candidate_sha256`, `spec_sha256`, `spec` jsonb,
  `harness_model_id`, `registered_by`, `purpose` ∈ {`evaluate`, `recorded_after`}, `registered_at`. Partial
  UNIQUE (`spec_sha256`) WHERE `purpose = 'evaluate'`, and partial UNIQUE (`candidate_sha256`, `split`) WHERE
  `purpose = 'evaluate' AND split <> 'discovery'`.
- **`hunt_trial_outcomes`**: `hunt_trial_id` (FK, unique), `status` ∈ {`computed`, `refused`}, `statistics` jsonb
  (every cell, including its refusal reasons), `active_series` jsonb (canonical variant, on the fixed grid below),
  `access_id` and `declaration_sha256` (NULL only for discovery), `outcome_sha256`, `computed_at`.

A statistical refusal is an outcome (`status = refused`). An infrastructure error (DB, I/O) is not: it propagates,
writes no outcome, and leaves the registered trial to be retried.

**Locking.** One session-level advisory lock per hunt, held for the whole of `evaluate` and taken by every freeze
and readout for that hunt. Evaluations within a hunt are therefore serial; there is no other lock and no ordering
question. Registration commits on a second connection while the lock is held.

`hunt_harness.evaluate(conn, spec, *, registered_by)`, in order:
1. Take the hunt lock.
2. If an outcome exists for this `spec_sha256`: for discovery return it; for validation and holdout re-pass the
   audited door (step 5) and return it.
3. **Refuse without registering** (no search): identity mismatch; unpriced lane; refused timeline; a
   `recorded_after` row for this candidate in this split (the split is burned); hunt in `HUNT_CLOSED`; for
   discovery, the hunt's discovery `evaluate` rows at `HUNT_BUDGETS[hunt]`; for validation and holdout, a spec not
   pinned in the frozen declaration (`spec_not_in_declaration`, recorded through `sql/340` after the door's own
   lock, as `result_ledger` orders it).
4. Insert the `hunt_trials` row, or find it (a retry after a crash reuses it: the same search against the same
   identity-bound data), and **commit** before any price read (the sql/340 "survives the caller's rollback"
   pattern).
5. Validation and holdout: pass the audited door; its access row commits before the price read.
6. Compute; for validation and holdout call `verify_outcome_access_provenance`; write the outcome.

**M is counted from `hunt_trials`, not outcomes.** A crashed or abandoned trial is a search. Exploratory charts
count too (programme rule 2), so the harness is the only sanctioned route to an outcome-bearing number on research
prices for a hunt.
- `tests/test_sealed_outcome_scripts_are_gated.py` is extended: any module under `scripts/` or `app/services/hunt*`
  other than `hunt_harness` that imports a research price reader fails. Notebooks and shells are outside it
  (residual).
- A look outside the harness is recorded as `recorded_after` rows, one per variant the recorder states was looked
  at; if unknown, one, flagged as a floor. It counts in M and burns that candidate's split.

**Budget and closure.** `HUNT_BUDGETS` (discovery `evaluate` rows per hunt) and `HUNT_CLOSED` (hunt → terminal
readout) are constants in `hunt_harness`, changed only by reviewed PRs: the #3387 PR sets a budget; a closure PR
records the terminal readout. The terminal readout is **"no demonstrated edge"** when discovery closes with no
candidate declared, or when the validation batch completes with no `PASS`; it lists each candidate's verdict, so a
control failure, a refusal and an undetermined result stay distinguishable.

**Trial register (#2829).** Each hunt carries `DeclaredTrial` entries `hunt-<n>-<split>`:
- **discovery:** added by the PR closing discovery. `searches` = the hunt's discovery rows (both purposes) with
  `registered_at` ≤ a stated closing timestamp. Slice 1 extends `DeclaredTrial`'s contract with this log-backed case
  for `searches > 1`: `evidence` gives the query, the timestamp and the sha256 of the ordered id list. `EXACT`, or
  `FLOOR` if any `recorded_after` row is flagged as a floor;
- **validation / holdout:** added by the declaration PR **before** the freeze (the prospective claim
  `freeze_preregistration` requires), `searches` = the pinned specs, `evidence` = the declaration doc's sha256.
- **Tripwire, at freeze:** the discovery entry's id-list hash must equal the log's at its timestamp, and no
  discovery row may be newer than it; every validation/holdout `evaluate` row must be a pinned spec. Otherwise the
  freeze refuses `register_disagrees_with_log`. Discovery-time screening readouts do not refuse; they are labelled
  `register_pending`.

## The audited door: validation and holdout
- **Validation.** A hunt's batch is one `PreregDeclaration` (`strategy_id = hunt-<n>-validation`, `v1`), claimed by
  `hunt-<n>-validation` via `declared_for`, frozen from `main` by `freeze_preregistration` before the look. Its
  hashed doc pins every candidate's `spec_sha256`, M, V[SR] with the trial ids it came from, the BY readout that
  flagged each candidate, and the power output. Only candidates with a discovery `evaluate` row, each once.
- **Holdout.** At most one declaration per hunt (`hunt-<n>-holdout`, `v1` only), freezable only once every pinned
  validation spec has an outcome. It pins every validation `PASS` together and the holdout end session.
  `evaluate` on holdout writes outcomes but **returns none**. `holdout_readout(hunt)` returns the verdicts, labelled
  `corroboration_partly_seen`, only when every pinned spec has an outcome; a pinned spec that cannot be computed is
  retried, or declared abandoned in a PR, and the readout then shows it `NOT_PASS_REFUSED`.
- **Atomicity.** Freeze-time numbers are computed under the hunt lock in one REPEATABLE READ snapshot.

## The evaluator: arm minus matched control
**Books.** For each formation t:
- the **control cohort** C(t) = every eligible **scored** name. Restricting to the signal's own domain keeps its
  history requirement out of the active return; the edge measured is *within* that domain (residual);
- the **arm cohort** A(t) ⊆ C(t) = the selected names. With ⌈f · N⌉ ≥ 1, A(t) is non-empty whenever C(t) is;
- same lag, h, points, weighting, lane and costs: the "same construction without the signal" (#2908/#2901).

**Fixed grid.** The active series is defined on **every** session from the first entry session to the last exit
session of the split's usable formations. T = the number of those sessions, known from the calendar before any
price is read.

**Calendar-time series (construction, after JT §I).** Each book has h slots with fixed weight 1/h. On session d,
slot k holds the cohort formed at t_k = d − lag − k (k = 0 … h − 1), if that formation is usable and its C(t_k) is
non-empty; otherwise the slot is **idle** and returns 0 in both books. Book return r(d) = (1/h) Σ_k r_k(d).

Within a cohort, weights are **equal and reset daily**: r_k(d) is the plain mean of its positions' returns on d.
Neither the daily reset nor the fixed 1/h across slots is costed, identically in both books (residual). A cohort's
return is 0 on its entry day if entry is at close.

**One position's return on session d** (ratio-basis corrected prices; P = the relevant point):
- entry day, entry at open: close(e)/open(e) − 1, less the entry cost; entry at close: the entry cost only;
- later days: (close(d) + div(d)) / close(prev) − 1, where prev is its previous session with a bar and div(d) is the
  cash dividend with ex-date d, divided by the same split ratio as the price;
- exit day at close: as a later day, less the exit cost; exit at open: (open(x) + div(x)) / close(prev) − 1, less
  the exit cost;
- **a session without a bar** for the name: the position is left out of that day's cohort mean. Its next bar's
  return spans the gap from its last close, dividends included. A name is never dropped after formation;
- **no bar at entry session e:** the position is never entered and never charged. It is left out of the cohort mean
  on every day of the hold (the other positions carry the cohort). A cohort with no entered position is idle;
- **no bar at exit session x:** exit at its last close on or before x, and the exit cost is charged on that session.

**Termination and censoring (construction).** A series whose last archive bar is before the archive's last session
has terminated at that bar. On that session its return is (1 + r) · f − 1, f the policy's terminal fraction, and it
leaves the cohort. No exit cost. A series whose last bar **is** the archive's last session is censored: no haircut,
marked at its last close. Classification uses the archive identity frozen in the spec, so a later archive
extension cannot reclassify a series within a trial. Termination is booked only for entered positions.

**Ruin.** Position returns are ≥ −100%, since every cost is proportional (see "Lanes"). r(d) is an average of daily
returns, not a compounded NAV, so no zero-wealth state carries over. A book return ≤ −1 + 10⁻⁹ on any session refuses
the cell (`book_ruin`).

**Active series.** a(d) = r_A(d) − r_C(d) on the fixed grid, net of costs. A no-signal spec (A ≡ C) gives a(d) ≡ 0
exactly under base cost.

**Descriptive tilts (not gating):** the slope of a on r_C, and the arm-minus-control mean of log as-traded price and
of trailing 63-session volatility (residual: tilts are reported, not neutralised).

## Inference
**Cells.** Each trial is computed per termination policy × {with, without dividends}, at base and at stress cost.
The **canonical cell** is base, with dividends, `zero_recovery`; it alone is stored as `active_series` and feeds
V[SR].

Per cell:
- **Lag (construction):** L = max(2h, ⌊4(T/100)^{2/9}⌋). The 2h floor covers the overlap of h cohorts and a
  margin; dependence beyond it is possible (residual).
- **HAC t** = mean(a) / NW standard error at L.
- **p** = `student_t_cdf`(−t, df), the lower tail of −t (no `1 − cdf` cancellation), df = ⌊T / L⌋ − 1, the number of
  non-overlapping L-blocks (construction; conservative against the normal, still asymptotic).
- **Statistical refusals (construction, frozen):** T < 10·L (`short_sample`); fewer than 30 non-overlapping
  formations with a non-empty arm, counting formations at least h sessions apart (`sparse_arm`); zero variance or
  a non-positive NW variance (`degenerate_variance`). Every `None`, exception or non-finite value from a shared
  statistics function becomes `Refused`.

**DSR (validation and holdout candidates only):**
- SR, skew and raw kurtosis from `trade_moments(a)`;
- T_eff = min(T, T · γ̂₀ / Ŝ_NW) at L (construction: a mean-based effective sample, applied to a Sharpe ratio;
  the paper assumes independence and offers no correction; negative dependence is not credited here, though the
  HAC t itself can still benefit from it — residual). T_eff ≤ 30 refuses (`short_effective_sample`);
- **V[SR_n]:** the ddof=1 variance of the canonical-cell per-observation Sharpe over every discovery `evaluate`
  trial **of this hunt** with an outcome. A Sharpe is computed for every outcome whose canonical series has
  non-zero variance, whether or not its other statistics refused. Fewer than 10 such trials refuses
  (`trial_population_too_small`). Frozen in the declaration with the trial ids;
- **N̂ = M, no correlation discount.** The paper's A.3: *"using M instead of N will overstate E[max{SR_n}]"*, i.e.
  it is conservative. v2's ρ̂ machinery is dropped;
- **M** = M_inh + every discovery row (both purposes) across all hunts + every spec pinned in every frozen
  validation or holdout declaration, at freeze time. Pinned specs are counted from the declarations, not from
  their log rows, so nothing is counted twice;
- id `hunt-calendar-active-dsr-v1` (the axis differs from `c6-deflated-sharpe-v1`).

**BY (programme-wide discovery screen).**
- m = M_inh + every discovery row across the programme at readout time;
- a trial's p is the **largest** base-cost p over its policy × dividend cells (every cell must clear the screen);
  p = 1 if any base cell refused, if it has no outcome, or for an inherited search;
- reject the largest k with p₍ₖ₎ ≤ k·q / (m·c(m)), q = 0.05; flag every p ≤ p₍ₖ₎;
- recomputed on every readout; a flag counts only in the readout pinned by a validation declaration.
- **Claim:** BY here is a screen deciding which candidates may be declared. Theorem 1.3 assumes a fixed family of
  valid p-values; this programme is sequential and adaptive and its inherited searches have no p-values, so the
  nominal FDR is **not** guaranteed (residual). Validation's t and DSR bars are the gate.

**Per-regime readout** (descriptive): mean(a) and session count per `classify_regimes` label of session d. No t.

## Verdicts
**Discovery** issues no verdict: statistics plus a BY flag.

**Validation and holdout**, per candidate. Base cells = policy × dividends at base cost; stress cells likewise. A
refused stress cell counts as a failed stress cell. First match wins:
1. `NOT_PASS_REFUSED`: any base cell refused (reasons listed).
2. `PASS`: every base cell has t > 3.0, DSR ≥ 0.95 and mean(a) > 0, and every stress cell has t > 3.0 and
   mean(a) > 0.
3. `PASS_CONTINGENT`: base as 2, stress not. **No capital, no holdout.**
4. `FAIL_CONTROL`: mean(a) ≤ 0 in every base cell.
5. `UNDETERMINED`: mean(a) > 0 in every base cell, and each base failure is t or DSR only. Never labelled "no edge"
   (programme rule 3).
6. `NOT_PASS_MIXED`: anything else, failures listed.

Tests cover each verdict **and** each precedence boundary (a case matching two rules, and each threshold at
equality).

## Power, before each validation and holdout look
`scripts/measure_3385_power.py --declaration <doc>` reads **stored discovery outcomes only** (the candidate's
canonical `active_series`), reads no prices, and is a readout, not a search. From the stored series it takes Ŝ_NW
at the target split's L. T_x is the target split's fixed-grid length, from the calendar.

It prints, for the canonical cell's t bar only, the minimum detectable annualised active mean at 50% and 80% power
under a normal approximation with Ŝ_NW treated as known: (3 + z)·√(Ŝ_NW / T_x)·252, z ∈ {0, 0.8416}. It also
prints whether T_x clears the `short_sample` floor. The output says, in words, that it is not power for DSR, for
the other cells, or for the joint PASS, and that Ŝ_NW is assumed to carry over from discovery. The discovery effect
is selection-biased upward, so no verdict is predicted from it. The declaration copies the output; the run
re-executes the script on the stored outcome hashes pinned in the declaration and refuses on any difference at 6
significant figures.

## Lanes and cost model (`hunt-cost-v1`)
Proportional costs, per side, at each position's entry and exit, in both books. Today's tariff applied to 1990–2024
is a **labelled counterfactual**: `cost_regime = tariff-2026-counterfactual` on every outcome.

| lane | status in v1 | charge |
| --- | --- | --- |
| `real_stock_long_x1` | **priced**, if the re-fetched fees page shows only proportional charges | the frozen half-spread band at the as-traded entry price (`cost_band_for`), per side, plus any proportional commission. Carry and FX are zero on this lane only under `COST_MODEL_ID`'s stated prerequisites (USD order, USD account, real settlement), which the outcome records. ⚠ If the page shows a **fixed per-order fee**, the lane is **unpriced → refused** in v1: a fixed fee needs a position size, which a return series does not have |
| `stock_cfd_long_x1` | **unpriced → refused** | 0.15% per side + band + 2¢/unit at ≤ $3 + (6.4% + benchmark)/365 per night, Friday ×3; needs a point-in-time benchmark rate (programme step 6) |
| `stock_cfd_short_x1` | **unpriced → refused** | historical borrow availability and fees are not observable |
| `index_cfd_hedge` | **unpriced → refused** | #2844 gross-exposure question |

Every run calls `cost_price_basis` on the archive and refuses unless it returns `as_traded`. A refused lane fails
before registration and costs no search (the `CARRY_CLOSURE` shape: a closure, never a zero posing as a measurement).

**Stress (construction; a sensitivity, not a bound):** arm positions are charged the larger of their base band and
`UNKNOWN_NOMINAL_PRICE_BAND` (the top frozen band); control positions keep the base band. Names already in the top
band get no extra charge, and real gaps or illiquidity can exceed it.
