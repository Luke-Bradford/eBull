## Splits and purge
Sessions are NYSE sessions (`us_market_status`).
- **discovery**: 1990-01-02 → 2008-12-31.
- **validation**: 2009-01-02 → 2021-06-28.
- **holdout**: ≥ `HOLDOUT_BOUNDARY`. This is a **corroboration** window, already partly seen (#3384 Finding 5).

An observation formed at session t has a label interval [entry, exit]: entry is t + lag, exit is entry + h − 1
sessions, with the entry and exit price points declared.
- **Horizon cap:** lag + h ≤ 63. The harness refuses larger values, so a purge can never exceed the embargo.
- **Purge:** an observation belongs to split S only if t, entry and exit all fall in S.
- **Embargo:** observations formed in the first 63 sessions of validation and of holdout are dropped. They are not
  moved to another split.
- **Fitting:**
  - every normaliser, rank or winsorisation is causal, using data ≤ t;
  - a cross-sectional transform is fitted within date t;
  - a threshold or constant used in validation is fitted on discovery only, and frozen in the spec before any
    validation look.

**Survivor conditioning** (#3384 Finding 1): every series trading before 2013-06-21 survives to at least that date.
So the whole of discovery, and validation up to 2013-06-20, is survivor-conditioned.
- Every trial spec carries a required field, `survivor_bias_direction` ∈ {`favours_arm`, `favours_control`,
  `unknown`}, with a one-line reason. It has no default.
- Every validation readout reports the pre-2013-06-21 and post-2013-06-21 sub-spans side by side. This is
  descriptive only: selecting either sub-span is a new trial.

## A trial
`TrialSpec` is a frozen dataclass. `spec_sha256` is the sha256 of its canonical JSON (sorted keys, compact separators;
the `PreregDeclaration.sha256` convention). Fields:

| field | content |
| --- | --- |
| `hunt_id`, `family` | e.g. `hunt-1`, `overnight_intraday` |
| `signal_id`, `signal_code_sha256` | registered callable, plus the sha256 of the module that defines it |
| `sign` | +1 or −1: the **directional prediction**, written before the look (rule 4), with `mechanism` and `competing_explanation` as text |
| `selection` | top/bottom fraction of the date-t eligible cross-section by score. Ties at the cut are **all included** (the #2240 threshold-row prevention entry), and the tie count is reported |
| `lag`, `h`, `entry_point`, `exit_point` | lag ≥ 1 session. `entry_point` / `exit_point` ∈ {open, close}. The signal sees bars ≤ t close, so the earliest entry is the open of t+1 |
| `weighting` | `equal` only in v1 |
| `lane` | `real_stock_long_x1` only in v1 (see "Lanes") |
| `split` | discovery, validation or holdout |
| `universe_identity` | `validated_ids_sha256` + price-archive identity + `termination_identity` |
| `cost_model_id`, `harness_model_id` | the frozen models |
| `survivor_bias_direction` | as above |

**Causality is structural.** The harness calls `signal(t, view)` with a view truncated at t's close. A signal cannot
index a later bar, because the view does not hold one. A test drives a signal that tries.

**Eligibility** is applied identically to arm and control, and uses only bars ≤ t (#3384 Input 4). A series is
eligible when all of the following hold:
- it is admitted on t;
- its bar on t is valid (positive prices, open and close inside [low, high]);
- it has volume > 0;
- its range is non-zero (high > low).

Per cohort, the harness counts the zero-range and no-volume exclusions for each book.

## Registration: the log comes before the number
New migration (next free number), holding two tables:
- **`hunt_trials`**: `hunt_trial_id`, `hunt_id`, `family`, `split`, `spec_sha256`, `spec` jsonb,
  `harness_model_id`, `registered_by`, `purpose`, `registered_at`. It has UNIQUE (`spec_sha256`, `split`) and an
  append-only trigger that rejects UPDATE and DELETE (the `sql/264` pattern).
- **`hunt_trial_outcomes`**: `hunt_trial_id` (FK, unique), `statistics` jsonb, `outcome_sha256`, `computed_at`.

`hunt_harness.evaluate(conn, spec, *, registered_by, purpose)` works in this order:
1. Insert the `hunt_trials` row and **commit** it on its own connection before any price read. A crash after this
   point still leaves the trial counted (the sql/340 "survives the caller's rollback" pattern). Re-registering an
   identical spec in the same split returns the existing row and does not add a search.
2. For validation and holdout only, pass the audited door (next section).
3. Compute and write the outcome row.

**M is counted from `hunt_trials`, not from outcomes.** An abandoned or crashed trial is a search. Exploratory charts
count too (programme rule 2), so the harness is the only sanctioned route to an outcome-bearing number on research
prices for a hunt.
- `tests/test_sealed_outcome_scripts_are_gated.py` is extended. A `scripts/hunt_*.py` that imports a research price
  reader directly fails the test.
- A look taken outside the harness is recorded after the fact as a `hunt_trials` row with
  `purpose = 'unregistered_look_recorded_after'`. It is counted, never omitted.

**Trial register (#2829).** Each hunt carries one `DeclaredTrial` per split it opened:
- `trial_id` is `hunt-<n>-<split>`, with `exactness = EXACT`;
- `searches` is the `hunt_trials` count, with the counting query given as `evidence`;
- the entry is added by the PR that closes that split's phase.

`hunt_harness` refuses a DSR or BY readout with `register_undercounts_log` when the register's count for a hunt is
below the log's. This is the mechanical tripwire, while the git-reviewed register stays the declaration.

## The audited door: validation and holdout
- **Validation.** Only candidates frozen from discovery are allowed, each tried once (UNIQUE on the spec). A hunt's
  validation batch is one `PreregDeclaration` (`strategy_id = hunt-<n>-validation`, version `v1`):
  - it is claimed by the register entry `hunt-<n>-validation` via `declared_for`;
  - it is frozen by `freeze_preregistration` from `main` before the look;
  - a hashed declaration doc pins every candidate's `spec_sha256`, the frozen M, and the power output.

  `evaluate` then calls `require_outcome_access_with_declaration` (`access_kind = 'evaluate'`) and passes only specs
  pinned in that doc.
- **Holdout.** At most **one** holdout declaration per hunt. It covers every validation `PASS` together, never one
  candidate at a time: the programme doc forbids opening the holdout per candidate and calling it pristine. Its
  readout is labelled `corroboration_partly_seen`.
- **Refusals.** A spec outside the pinned set is refused before any price read, with `spec_not_in_declaration`. The
  refusal is recorded through `sql/340`.

## The evaluator: arm minus matched control
**Books.** For each formation t in the split:
- the **arm cohort** A(t) is the eligible names selected by `sign · score`;
- the **control cohort** C(t) is **all** eligible names on t;
- both have the same lag, h, entry and exit points, weighting, lane and costs. This is the "same construction
  without the signal" of the #2908/#2901 lesson.

**Calendar-time series.** Following Jegadeesh–Titman, each book holds h overlapping cohorts, each with 1/h of the
book. The book's return on session d is the mean over its live cohorts of that cohort's equal-weight return on d.
Each position's return is computed as follows:
- on the ratio-basis corrected series;
- dividends are credited on the bar date inside (entry, exit]. #3384 Finding 2 leaves the ex-date semantics
  unverified, so every readout is computed **both** with and without dividends, and the two must pass jointly. That
  counts as one search, like the register's robustness fan;
- a termination inside the hold is realised at the last close times the policy's terminal fraction, under each of
  `PROGRAMME_POLICIES`;
- the first day is marked from the entry point, and the last day to the exit point.

**Empty arm slot.** If A(t) is empty, that cohort's slot holds C(t), so it contributes zero active return. Exposure
therefore matches the control on every session, and no cash drag counts as signal. The harness reports:
- the number of empty-arm formations;
- the distribution of arm names per cohort. No minimum is imposed, because none is published.

**Active series.** a(d) = r_A(d) − r_C(d), net of costs on both books, one value per session. This single series
carries every statistic.

## Inference
All statistics are computed per termination policy, composed by weak-Kleene, with `zero_recovery` governing (the
#2901 composition, imported). With T sessions in the split after purge and embargo:
- **HAC t:** mean(a) / NW standard error, lag L = max(h, ⌊4(T/100)^{2/9}⌋). The signed statistic is t_s = sign · t.
  Using h as a floor covers the cohort-overlap autocorrelation the JT averaging leaves in place.
- **One-sided p** in the declared direction: p = Φ(−t_s), evaluated as a survival function.
- **DSR** on the daily active series:
  - SR, skew and raw kurtosis come from `trade_moments(a)`;
  - T_eff = T · γ̂₀ / Ŝ_NW, the ratio of the IID variance of the mean to its HAC variance at the same L. This is by
    construction: the paper assumes serial independence, so T_eff is its stated adaptation;
  - V[SR_n] is the ddof=1 variance of the per-observation active Sharpe over **every discovery trial with an outcome
    in the programme log**. That is all measured screens, not a survivor subset, which removes the register's
    documented measured-subset bias for this programme;
  - ρ̂ is equation (8) over those trials' active series on common sessions;
  - N̂ is equation (9) with M = M_inh + |`hunt_trials`| (all hunts, all splits), **frozen in the validation
    declaration before exposure**, the #2901 rule;
  - a new id, `hunt-calendar-active-dsr-v1`, is used, because the axis differs from `c6-deflated-sharpe-v1` (trade
    axis).
- **BY (programme-wide, discovery screens).**
  - m = M_inh + |discovery rows in `hunt_trials` across the programme| at readout time.
  - Inherited searches have no p-value and enter as p = 1. This is valid, because adding p = 1 hypotheses only
    raises the step-up threshold's denominator.
  - Rejection: take the largest k with p₍ₖ₎ ≤ k·q / (m·c(m)), and flag every p ≤ p₍ₖ₎.
  - It is recomputed on every readout, never reset per family or per hunt. A flag can therefore be withdrawn as m
    grows. A candidate must be flagged **at the moment its validation declaration freezes**, and that readout's m
    is pinned in the declaration.
- **Per-regime readout** (descriptive, never gating): a(d) grouped by `classify_regimes` label on each cohort's
  formation date. It reports mean, HAC t and session count per label, and nothing is selected from it.

## Verdicts
**Discovery** issues no verdict. Its readout is statistics plus a BY flag. Discovery is not evidence.

**Validation**, per candidate. Evaluated in order; the first match wins:
1. `NOT_PASS_REFUSED`: any gating statistic refused under any policy, with the reasons listed.
2. `PASS`: t_s > 3.0, **and** DSR ≥ 0.95, **and** mean(a) > 0 in the declared direction, under the base cost arm and
   with and without dividends. The stress arm also passes.
3. `PASS_CONTINGENT`: as 2, except the stress arm fails (evaluated, not refused). **No capital, no holdout.**
4. `FAIL_CONTROL`: sign · mean(a) ≤ 0 under every policy.
5. `UNDETERMINED_AT_THIS_POWER`: the only failed conditions are t_s > 3 and/or DSR. It is never labelled "no edge"
   (programme rule 3).
6. `NOT_PASS_MIXED`: anything else, with every failed condition listed.

## Power, before each validation look
`scripts/measure_3385_power.py --declaration <doc>` reads **discovery only** for the candidate: σ̂ and Ŝ_NW of a(d).
It also counts validation sessions with a non-empty arm cohort from **signal selection alone**. No return is read for
that count.

It prints the minimum detectable annualised active mean at t_s = 3 for 50% and 80% power:
(3 + z)·√(Ŝ_NW / T_v)·252, with z ∈ {0, 0.8416}.
- The declaration copies the output verbatim, and the run re-executes the script and refuses on a mismatch (the #2901
  rule).
- The discovery effect is selection-biased upward, so no verdict is predicted from it.

## Lanes and cost model (`hunt-cost-v1`)
Costs are charged **per side**, on each cohort's entry and exit, on both books. Today's tariff applied to 1990–2024
is a **labelled counterfactual**: every outcome carries `cost_regime = tariff-2026-counterfactual`.

| lane | status in v1 | charge |
| --- | --- | --- |
| `real_stock_long_x1` | **priced** | frozen half-spread band keyed on the as-traded entry price (`cost_band_for`, `as_traded`), per side. Carry and FX are structural zero (`COST_MODEL_ID`'s declared lane) |
| `stock_cfd_long_x1` | **unpriced → refused** | 0.15% per side + the band half-spread + 2¢/unit per side at an as-traded price ≤ $3 + (6.4% + benchmark)/365 per night, Friday ×3. The benchmark needs a point-in-time rate series (#3384 slice 2b / FRED ingest, programme step 6) |
| `stock_cfd_short_x1` | **unpriced → refused** | historical borrow availability and hard-to-borrow fees are not observable, and the programme doc requires an executable borrow rule, not an assumption |
| `index_cfd_hedge` | **unpriced → refused** | #2844 gross-exposure question (see "What this spec fixes") |

A refused lane fails before registration, so it costs no search. That is the `CARRY_CLOSURE` fail-closed shape: a
closure state, never a zero pretending to be a measurement.

**Stress arm:** arm legs are charged `UNKNOWN_NOMINAL_PRICE_BAND` (the maximum frozen band), control legs the base
band. The spread therefore widens exactly on the trades the signal selects, which is the programme doc's
requirement, with no invented state threshold. Hunt 1 (families 1–3) is long-only real stock, so v1 prices all of it.

## Declared residuals
- Tariff counterfactual. The band table is one summer's closing-hour quotes (`cost_model` limits 1–3), applied to
  1990.
- Survivor conditioning before 2013-06-21. Its direction is declared per trial, not corrected.
- Asymptotic p-values: BY and the t bar inherit their validity.
- Validation is a previously examined window (#3384 Finding 5). Only forward paper confirms (programme step 8).
- V[SR_n] and ρ̂ come from discovery, while the candidate's SR comes from validation: the same units, different
  windows.
- Equal-weight only. A survivor's construction (sizing, turnover band, hedge) is frozen later.
