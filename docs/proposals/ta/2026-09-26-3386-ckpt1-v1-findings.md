# #3386 spec v1 — Codex ckpt-1 findings (verbatim)

References: **S** = [#3386 spec](2026-09-26-3386-hunt-feature-store.md); **H** = [#3385 spec](2026-09-26-3385-hunt-harness.md). Numbers after S/H are lines. Conditional and inherited gaps are marked.

1. **S48–52,136–139:** “a stale store is … never a wrong read” contradicts the declared metadata-identity residual. Unchanged metadata can identify different content.

2. **S118–121:** Quarantine **data/coverage** is absent from the shown identity. Changing coverage or masking under an unchanged quarantine rule version can change loaded bars, dividends and exclusions without invalidating the cache.

3. **S136–139:** The residual is broader than price edits: dividend amounts, nontrivial split-factor values, volumes and interior bar dates can change while counts/ranges remain unchanged. These can change signals and adjustment bases.

4. **S43–44,69–70:** Live benchmark revisions can change regime readouts under identical `store_key` and `store_content_sha256`. The recorded digest does not identify everything used by the outcome.

5. **S54–58:** `load_panel -> HuntPanel` cannot omit regime labels: `HuntPanel.__post_init__` requires one per session. Specify the intermediate representation and live-label attachment step.

6. **S43–58:** A miss already computes regimes inside `load_hunt_panel`; subsequent reconstruction could compute them again. Specify exactly when labels are loaded so hit/miss paths use equivalent snapshots.

7. **S56–67:** Publication precedes the harness’s post-computation identity check. A rejected computation can leave a cache published under its old key; no invalidation-on-rejection rule exists.

8. **S51,67 — conditional:** The programme lock does not establish a snapshot against archive ingestion. Before/after identity checks miss an A→B→A transition and unchanged-metadata edits during a multi-query build.

9. **S69–70:** The content digest covers array hashes, not `load_counts`, although counts enter statistics. Manifest-only count changes can alter outcomes without changing either recorded store identifier.

10. **S136–139:** A digest cannot reproduce deleted bytes. Automatic removal of other stores directly undermines “results stay reproducible from the recorded `store_content_sha256`.”

11. **S48–52,69–70:** Content is recorded after computation, not pinned by trial identity. Following an invisible edit, warm and rebuilt caches can supply different inputs for the same trial specification.

12. **S28,49–50 — conditional:** New key/gating logic in `hunt_harness` is not automatically code-hashed: `MODEL_CODE_MODULES` excludes that module. Put consequential logic in hashed modules or explicitly bind it.

13. **S26–30,118–121 — RULE:** The complete-identity claim omits H448–453’s explicit exception: numpy/stdlib versions are recorded, not identity-bound. Cite that residual rather than implying complete coverage.

14. **S40–42:** Checksums do not validate schema. Specify required files, format validation, dtypes, dimensions, column lengths, offsets, unique IDs, session ordering, ordinal bounds and allowed exclusion/termination codes.

15. **S35–39:** CSR lacks a stated final-offset/length convention, integer types for IDs/offsets, and termination-code mapping. Empty dividends and the final series are decoding edge cases.

16. **S38–39:** Sessions use proleptic date ordinals; bars/dividends use dense session indices. Make the distinction explicit and validate it—confusing them still produces valid integers.

17. **S39–42:** Recovery semantics omit malformed JSON, unsupported formats, missing hash entries, truncated `.npy` files and structurally invalid but correctly hashed arrays. Specify miss versus infrastructure error.

18. **S35–42 — conditional:** Explicitly require numeric loading with pickle disabled and reject object arrays. Expected numeric content alone is not an enforced file invariant.

19. **S40–42 — conditional:** Hashing a pathname and reopening it permits the checked bytes and loaded bytes to differ. Hash the bytes actually decoded or establish immutable file handles.

20. **S35–40,69–70:** Deterministic serialization is unspecified: mapping order, array byte order, code assignment and hash-map serialization. Equivalent panels can otherwise produce different digests.

21. **S127–129:** Field equality does not check iteration order. Reordering series/dividends can change valid signals that iterate mappings and floating-point reductions.

22. **S56–57:** `os.replace(temp_directory, existing_nonempty_directory)` cannot repair an existing corrupt cache directory. A miss caused by corruption therefore lacks a working replacement procedure.

23. **S56–67:** The described readback occurs after publication. Validate the temporary artifact before publishing or deleting previous caches; otherwise a failed build can replace usable state.

24. **S56–67:** Atomic rename alone does not specify crash durability. Interrupted writes, orphan temporary directories, restart recovery and cleanup ordering are missing.

25. **S67 — conditional:** “two builds cannot race” assumes every caller shares the same database lock. Direct helper calls, A/B tooling or different databases using one checkout are not covered.

26. **S65–67:** Deleting every sibling directory needs an ownership rule for temporary/in-progress builds. Define whether deletion failure invalidates an otherwise successful build.

27. **S54–59:** The lower-level store receives an opaque key, with no stated discovery-boundary check. An erroneous key passed for validation/holdout could persist protected prices.

28. **S73–75 — RULE:** “only `hunt_panel` … may import it” is not enforced by the proposed test change. The existing test also permits `hunt_harness`, grandfathered readers and gated scripts (`test_sealed_outcome_scripts_are_gated.py:487–494`).

29. **S140–141 — RULE:** Discovery needs no validation door, but research outcomes still require registration. Direct `numpy.load` bypasses the module-import test; distinguish that inherited enforcement residual from “no new route.”

30. **S33,48 — conditional:** Importing `hunt_harness.canonical_form` into the pure store creates a dependency cycle and violates the intended DB-free boundary. Specify where key canonicalization lives.

31. **S87:** Existing `Prefix` supports numeric values and multiplies each item by a factor (`hunt_view.py:54–85`). It cannot directly implement a lazy `datetime.date` prefix.

32. **S86–92:** Require both new cuts inside `rebased_view`, as the current view contract requires. Caller-only slicing would weaken the existing protection against wiring mistakes.

33. **S87–92,130–131:** Boundary tests omit negative indices, reverse/stepped slices, empty histories, future-only dividends, ex-date exactly t and mismatched date/ordinal lengths.

34. **S89:** Dividend prefixes must use their own sorted ex-date ordinals, not bar positions. Gap dividends can exist without a corresponding bar; preserve them and test that alignment.

35. **S84,95–97:** “Paid history” is inaccurate: the archive supplies ex-dates, not payment dates. Payment-timing features cannot be inferred from these fields.

36. **S89–97 — conditional:** Ex-date ≤ t does not establish that the archived amount was available in that form on t. Announcement/revision timestamps are absent; explicitly declare the point-in-time-data assumption.

37. **S91–92:** Reading NaN does **not** guarantee a nonfinite score. Comparisons, filtering and fallback branches can return finite scores. The harness filters final scores only.

38. **S89–92 — RULE:** Cite and reconcile H475–478: conflicting, negative or nonfinite dividends refuse a cell. The new signal-level treatment can instead exclude affected names before those cells encounter them.

39. **S89,125 — inherited:** `hunt_panel.py:170–180` collapses dividends into a dictionary without an explicit conflicting-duplicate check. The store cannot recover evidence already discarded; round-trip equality will preserve that defect.

40. **S89 — inherited/conditional:** The dividend query checks quarantine coverage, not the dividend date’s bar exclusion. Historical dividend amounts may remain visible where corresponding price fields were masked; define the intended policy.

41. **S89–91:** Positive finite closes do not guarantee finite, nonzero `k = traded_close / ratio_close`. Extreme ratios can overflow/underflow; new dividend multiplication extends that existing unchecked arithmetic.

42. **S90–91,130–131:** “A later split cannot move it” needs a numerical contract. Cancellation through rounded ratio-basis values need not be bit-exact; test multiple/reverse splits, extreme scales and split/ex-date coincidences.

43. **S87–92 — inherited:** Lazy prefixes expose mutable `_values`, `_end` and `_factor`. Signals can inspect future backing data or mutate shared arrays; extending prefixes extends this code-review-only residual.

44. **S109–117 — RULE:** “Nothing leaks” and “no randomness exists” overstate enforcement. Discovery-only fitting remains a provenance obligation; numpy is allowed and exposes randomness. Cite H125–129’s explicit non-sandbox limitation.

45. **S104–107:** Scoring nothing on other sessions times **both** books. It does not make a pure calendar premium identifiable; constant-score tie selection may instead measure an arbitrary subset.

46. **S125–129:** “Series with any difference” cannot alone detect session/count differences, missing or extra series, or global metadata mismatches. Give each a separate full-population assertion; use NaN-aware comparisons.

47. **S127–133:** Panel equality does not establish identical hit/miss outcomes or live-regime wiring. Add pure synthetic computation parity and integration checks that validation/holdout never access the store.

48. **S20–21,127–129 — POPULATION:** Zero loaded terminations covers the admitted, successfully loaded discovery population only. It does not establish absence among rejected/unloaded series; the proposed A/B also provides no empirical terminal-case coverage.

49. **S15–24 — SAMPLE:** Two signals on one dev corpus do not establish general trial speedup. Even excluding books, loading is approximately 42–44% of the reported totals, not roughly one third.

50. **S19–20:** `_form_cohorts` does more than eligibility: scoring, selection, cohort construction and price/volatility tilts (`hunt_compute.py:290–327`). Calling its timing “eligibility only” misattributes the work.

51. **S35–39,56–58,67:** Missing resource edge: concatenation, checksumming, live-panel retention, reload and `_index` reconstruction can overlap large allocations. A ~0.8 GB disk estimate establishes neither peak RAM nor required temporary disk space.

52. **S7,133 — SAMPLE:** `dev hunt_trials = 0` establishes only that database’s current state. It does not support the unqualified claim that changing the model ID costs nothing elsewhere.
