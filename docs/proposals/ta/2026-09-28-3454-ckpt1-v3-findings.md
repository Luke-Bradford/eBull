Verbatim from `codex exec` on spec v3. Disposition in the spec's Status section.

1. **Framing verdict: no, as an unqualified confirmatory claim.** The amendment and relaxed admission are now honestly disclosed; low power alone is no objection. But “not a confirmatory contaminant” exceeds the audit: [the existing census](docs/proposals/ta/2026-09-25-3384-hunt-admissibility-census.md) lists additional overlapping studies, including return autocorrelation and range reversal. Different populations and an adverse finding do not establish independence.

2. **Round-2 findings still inadequately handled:** **#1, #3–#7, #22, #24, #25**, some partially. **#2, #19–#21, #23 and #26’s stated boundary requirements** are handled or superseded. Details below; statistical-design deferral is sound except where it would defer the binding cost-to-return relationship itself.

3. **Arithmetic checks pass.** `(0.169−0.08)×5/(252×2) = 0.0008829365`: **8.829 bps per side**, **0.08829 percentage points**, **0.17659 points round trip**. The illustrative power probabilities also check out.

4. **Commission cancellation now passes (#19).** With the same additive commission \(c\), \(\{(s_e+c)+(s_x+c)\}/2-(b_i+c)=d_i\). This is exact cancellation in the newly defined spread difference; it does not establish cancellation in return factors.

5. **Still #3:** admitting upward biases does not correct or bound them. Validation qualification and both headrooms still use the affected series.

6. **Still #4:** validation registration supplies durable closure, but substantive **pre-look** refusal still closes through a later `HUNT_CLOSED` edit. There is no durable lineage-level refusal record for the interval before that edit. The family/hash check and registration also need to share the programme lock.

7. **Still #5:** four whole files are not the whole dependency set. For example, `result_ledger.py`, `prereg_contract.py` and `strategy_result.py` affect declaration acceptance but are outside those pins and the computation-module hashes.

8. **NEW — circular declaration hash.** The declaration hashes all of `trial_register.py`; its required validation register entry contains the declaration’s hash. Updating either changes the other. Split register data from pinned decision code or define an explicitly non-circular hashing contract.

9. **NEW — closure invalidates subsequent readouts.** Adding `HUNT_CLOSED`/`CLOSED_LINEAGES` changes the pinned harness file. Subsequent readouts therefore refuse their own required closure update. Define an immutable final promotion artifact or a compatible post-closure readout rule.

10. **NEW — stress remains a historical gate.** Required harness `PASS` demands passing stress cells; base success with stress failure produces `PASS_CONTINGENT` in [the actual verdict function](app/services/hunt_inference.py:697). V3 must explicitly define base-only qualification while preserving the frozen computation.

11. **Still #25; NEW counting error:** BY’s discovery count can rise by two, but **global M rises by three**: reregistration + H recording + validation reservation. Evaluation replaces the reservation and adds zero thereafter. The asserted global M+2 contradicts [the existing counting rule](app/services/hunt_door.py:295).

12. **NEW — register identifier violates its contract.** `hunt-3-reregistration` is rejected: `hunt-` identifiers allow only discovery/validation/holdout suffixes. Merely allowing the name would still exclude it from `M_inh`, whose filter excludes every `hunt-` entry. Rename it or explicitly amend both rules.

13. **NEW — register tripwire remains unspecified.** Reregistration does not supply the required `hunt-3-discovery` log evidence and `hunt-3-validation` declaration claim. H’s recording must remain in the actual log-count audit even though it is excluded from discovery **outcome** populations.

14. **Still #7/#22 — equal units do not establish the binding implication.** A bound on mean \(d_i\) does not bound the portfolio drag of uniform historical δ. Entry/exit asymmetry, heterogeneous bands, returns and cost covariance remain unbounded; calling them residuals leaves capital acceptance exposed.

15. **NEW — “first-order equal” needs qualification.** Even for one dividend-free terminal factor, the equivalent symmetric increment is  
    \[
    \delta_{\rm eq}=\frac{s_e+s_x+2c}{2+s_e-s_x}-(b+c).
    \]
    With \(b=.005,c=.001,s_e=.002,s_x=.010\), \(d=.001\), but \(\delta_{\rm eq}=.001028112\). At a fixed positive baseline, asymmetry has a first-order effect in the spread perturbations; it is second-order only when expanding all costs around zero.

16. **Still #24:** matching the δ=0 outcome does not pin the input snapshot. Changed inputs can preserve baseline aggregates while changing cost sensitivity, and data can change between bisection calls. Bind every δ evaluation to one immutable panel; bind and persist H_val likewise.

17. **NEW — outcome hash includes provenance.** It hashes `spec_sha256`, access ID and declaration hash alongside numerical output. A hunt-3 discovery recomputation cannot reproduce hunt-2’s full digest using hunt-3 metadata. Specify replay against the source row’s identity and provenance, similarly for H_val. [Hash implementation](app/services/hunt_harness.py:1026)

18. **NEW — bisection lacks guaranteed monotonicity.** I reproduced an evaluator counterexample: one entered position plus one unentered cash allocation, prices \(1\to.01\to10^{-6}\), held five sessions. Increasing hs from .005 to .055 improves summed daily returns from −.504876 to −.504649. Arithmetic portfolio returns need not decrease with costs; establish suitable monotonicity or use a solver that certifies the feasible interval.

19. **Still #6; NEW boundary ambiguities:** zero headroom is returned without the previously requested non-positive-headroom disposition; capped headroom needs a numeric operational value, namely .05. Also specify whether “any evaluation refuses” includes reported stress cells or irrelevant inference failures—otherwise those become additional capital gates.

20. **NEW — sensitivity-look accounting/access is incomplete.** Commit H’s accounting record before its first computation, including failed/crashed attempts; explicitly define the whole prescribed bisection as one counted sensitivity procedure. Define H_val as part of the already-consumed validation look, with retained access provenance: ordinary `evaluate` is closed, while another outside-look recording changes accounting and readout qualifications.

21. **NEW — provisional verdict needs a terminal transition.** If forward PASS against H later fails against H_val, explicitly finalize the **original endpoint evidence** against `min(H,H_val)` and close the route. Specify disposition when H_val is unavailable; a provisional PASS must not permit additional sampling or leave a permanently pending capital route.
