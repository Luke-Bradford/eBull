## The surface question — settled, and NOT the way this doc first argued

This doc originally argued that re-introducing a flat card "completes #691" and reverses nothing, on the grounds that `docs/settled-decisions.md` holds no card/surface decision. **Reading the actual surfaces falsified that.** `components/instrument/Pane.tsx:32-47` documents design-system v1 as deliberately borderless **editorial chrome**: it already replaced a rounded card (border + shadow + fill) with a hairline top-rule + small-caps title, on an explicit rationale — financial operators **scan across panes for cross-pane signal**, so the grid must read as one document, not a board of cards. `StatTile.tsx` follows the same rule (#1592). That IS #691's completion; adding a card back into the Pane grids would reverse it.

**Decision (2026-07-24, recorded on #1908):** editorial chrome stays the base. **No card variant** is introduced into any Pane scanning grid. The "stats float in empty space" complaint is answered by **spacing / grouping / density inside editorial chrome** — that promotes **PR-5 from a cleanup tail to the substantive fix** for issue item 2. Encoded in `.claude/skills/frontend/design-system.md`.

PR-1 is therefore reduced to token extraction, folded into whichever sub-PR first needs a token rather than shipped as a standalone repaint.
