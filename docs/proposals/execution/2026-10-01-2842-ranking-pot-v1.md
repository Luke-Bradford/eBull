# Ranking-pot-v1: the v1.5 ranking engine as a monthly demo portfolio, with every position's factor reasons (#2842)

round 3's IMPL findings are binding obligations on the slice PRs (Appendix A).
Source: supervisor comment on #2842, 2026-10-01 16:17Z (operator direction quoted there), and the #2437 queue revision

## 1. What this is

**Mechanism (hypothesis).** The house ranking (v1.5-balanced: quality, value, turnaround, confidence, momentum,
sentiment, additive penalties, the Calmar reward; `.claude/skills/ranking-engine/SKILL.md`) has scored about 3,900
names on most days since 2026-07-23 and has never selected a trade. Hypothesis: a book that holds the best-ranked
feasible names under a buy/hold band earns more per open position-day than the same policy with the ranking's order
reassigned to other names at random, and beats SPY over the same period.

**What the selection test measures.** Whether the real assignment of score paths to names beats random assignments
inside one fixed policy (same universe rules, bands, exits, costs, calendar; §9.2). It is an **observational
permutation comparison**: its p-value is a valid test only under an exchangeability assumption (§9.2) that the design
does not guarantee. Read a rejection as: "within this policy and under that assumption, the real order did better than
random orders". The order includes what the ranking takes from each name's own past prices (momentum, the
realized-risk penalty) and the exposures it induces (sector, size, beta, volatility). Eligibility is shared by every
book, so the comparison covers the ranking's ORDER only, not its contribution through eligibility (the score gate in
R). Not risk-adjusted; does not isolate a family or the thesis engine. §9.4 reports exposures for every book.

**What it is not.** A claim that any one position wins.

**Tier.** Demo only. Purpose `demo_trial` (§7.1): every capital, live and promotion chokepoint refuses it. Long only,
unlevered (`settlement_type='real'`). A pass is an argument on #2437, never an authorisation (§9.3).

**Explainability.** Every entry carries a ticket (§6), written before the order.

### 3.3 Power (said up front)

Over F, ≈1-year price returns (751 of 788 names with a valid bar 365–372 days back) had median 0.062 and SD 0.424. A
random 25-name basket's mean then has SE ≈ 0.083 (finite-population correction 0.984), and a one-sided 2.5% bar sits
≈ +16.3 points above the random mean. Normal-tail power at a true edge of +3 / +6 / +10 points a year: **0.05 / 0.11 /
0.22**.

A static basket held a year, normal tails, today's feasible survivors, a different statistic from §9.1's: an
order-of-magnitude guide only, not a power calculation for this test. It is enough to say a realistic premium is
unlikely to be confirmed at one 12-month look; nothing here shows 24 months suffices either. §9.3 has two looks, and a
non-pass reads "not demonstrated", never "no edge".

**The executed book's decision (slice 5a, by construction; Codex ckpt-1's 37 items disposed in the slice PR).**
Slice 5 is split: **5a** the executed book's records and its §4 step 4 in the rebalance job (no broker I/O); **5b**
the loader, the executor and the 15:00 UTC job (§7.2); **5c** exits, protection repair, the loss check, the
activation script and precheck, the wind-down stamps and the `completed` writer (§7.3, §7.4). `ranking_pot_exec.py`
is policy-hashed. `sql/449` adds four append-only tables, each written only inside the rebalance transaction that
inserted its decided attempt (the trigger compares the attempt row's `xmin` with the current transaction id, and
requires `sql/446`'s SHARE lock on the state events), so a decision and its records commit together or not at all:
- `ranking_pot_exec_rebalances`: one header per decided attempt taken in `executing`, `halted_loss` or
  `halted_operator` (the trigger checks the latest state event; the SHARE lock, taken by `begin_rebalance` before the
  snapshot, makes it the state the decision read). It records the state, `entries_allowed`, the `v1_active` reading,
  the counts, and the **classification** the decision read: every non-terminal lifecycle (id, name, slot, status,
  trade status) and the ids of every lifecycle classified `closed`. In `shadow_only` nothing is written.
- `ranking_pot_exec_lifecycles`: one per executed `enter` row: attempt, name, slot (1..N), `replaces_lifecycle_id`
  (the lifecycle this rebalance stamps whose slot it takes, else NULL), its `strategy_signals` row
  (`ranking-pot-v1`/`v1`, `entry`, `fired`, signal bar = the snapshot's `last_session`, fill bar = the target session,
  fill price = the snapshot close: the PLANNED basis, as v1's signals carry the pack's), the §6 ticket (canonical JSON +
  sha256). The trigger checks the signal's strategy, version, name and fill bar against the attempt.
- `ranking_pot_exec_decisions`: the §5.2 rows, one per (attempt, name); every row for a held or entering name names its
  lifecycle (same declaration, same name), an `enter` row its own new lifecycle.
- `ranking_pot_exec_exit_stamps`: one per lifecycle (its key), `exit_session` and reason, sourced from exactly one of
  the attempt (its `exit` row for that lifecycle; `exit_session` = the target session) or a `winding_down` event of the
  declaration (5c; `exit_session` = `ranking_pot_step.wind_down_session`). First writer wins: the rebalance holds the
  SHARE lock that a wind-down event's insert waits on, and a later stamp attempt is a no-op (r3-66).

**Classification (the reader, inside the rebalance's REPEATABLE READ snapshot).** Via signal → funding decision (one
per signal) → trade (one per decision): no funding decision → `entry_pending` while the New York date is not past the
target session, else `expired` (global and time-based, so 5b, 5c and `completed` read it identically; 5b's loader
refuses any lifecycle whose target session is not today, so after it no authority can be written); `rejected` →
`refused`; `allocated` with no trade, or the trade `planned`, `submitted` or `reconcile_required` → `entry_pending`
for §5.1's counting (the raw trade status is kept; 5c reads exposure from the trade, never from this label);
`open` / `closing` → `open`; `failed` → `failed` (the existing reconciliation's terminal no-position state; a late
fill reopens the trade and the lifecycle is held again); `closed` → `closed`. `expired`, `refused`, `failed` and
`closed` hold nothing and release their slot. Every later rebalance's target is in a later month than any earlier
lifecycle's target session, so no lifecycle the reader can call `expired` is still authorisable. Held lifecycles
must have distinct names and distinct slots (the reader raises otherwise).

**`recently_exited`** = names of lifecycles classified `closed` now and not in the previous header's `closed` set
(the latest header of the declaration; none → every `closed` lifecycle counts, and none exists before activation).
Timestamp-free and resurrection-safe: "closed since the previous decision's snapshot".

**Slots (r3-99).** A held lifecycle keeps its slot until it is `closed` or `failed`. Free = {1..N} minus held slots
(stamped ones included). `ranking_pot.decide` counts this rebalance's exits as capacity, so entries take, in entry
order, the free slots in ascending index, then the slots of the lifecycles this rebalance stamps, in ascending
index, recording `replaces_lifecycle_id`. 5b obligations: inside the authority transaction (not only before I/O), an
entry with `replaces_lifecycle_id` defers `pot_slot_not_released` until that trade is `closed` or `failed` and its
proceeds are booked to the slot (slice 5b: a deferral writes nothing and is retried that session); any refusal, or a
deferral still open when the target session ends, leaves the slot in cash until the next rebalance.

**Entries allowed** iff the state is `executing` and the snapshot shows no AI-trial declaration `active`; names that
would otherwise enter are `not_selected:entries_halted`. The rebalance reading is recorded, not authoritative: 5b
re-checks `v1_active` and the pot state under locks in the authority transaction (a stale "inactive" reading is
caught there; a stale "active" one only withholds entries). The decision uses the real order and the same
`ranking_pot.decide` as the shadow. The rebalance job's two `shadow_only` guards become "the state the fire started
in"; a state change during scoring rolls back and retries next fire.

A refused or skipped month makes no rank decisions in any book (rank exits need a ranking); protective exits continue.
All books skip the same months. One rebalance per `(declaration_id, target-session month)`.

## 5. Decisions (pure; one function for every book)

### 5.0 Population and universes (own facts only)

- **S₀:** the instrument ids scored in the last run before the freeze, frozen. No book ever enters a name outside S₀.
- **R_t (hold rules)**, on the name's **own** facts: in S₀; `is_tradable`; `us_equity`; its own score in the run finite
  and > 0; `completeness_tier` present and ≠ `insufficient_data`; `coverage.filings_status = 'analysable'`;
  overlaid cap ≥ the breakpoint.
- **F_t ⊆ R_t (entry rules):** `ai_trial_pack.is_eligible` with the name's own score; MAX valid and ≤ the cut; ATR14
  (house Wilder `atr_series` on the latest price segment, as v1) finite with `0 < 3 × ATR14 < ask`.
- R_t and F_t are **identical in every book**. Books differ only in the **order** used to rank R_t (§9.2).
- Quote freshness, spread and MAX never cause an exit.
- The quote rule is evaluated at the snapshot's `as_of` (§4 (*): between 23:30 and 12:00 UTC), after the close; the
  v1 trial applies the same rule from 23:30 UTC every weekday and records its eligible count per run, so a production
  F far below §3.1's intraday figure would show there first.

### 5.1 Rules, in order

The **held set** = open positions + entries planned, submitted or uncertain − positions carrying a due exit stamp.

1. **Exit** each held position not in R_t (`ineligible:<first failed rule>`) or with R-rank > 2N
   (`rerank_out_of_band`). A position already carrying an exit stamp keeps it (`exit_pending`), even back in band.
2. **Enter**, in rank order, names in F_t not held and not exited this rebalance, with F-rank ≤ N and R-rank ≤ 2N,
   until held + entering = N. Unfilled slots stay cash (`slot_unfilled`, counted).
3. `winding_down` needs no rebalance: the wind-down event itself stamps every executed position's exit for the next
   NYSE session, and the shadow and controls close all positions at that session's close (§9.1). No scoring or input
   check can delay it. After it, no rebalance runs.

### 5.2 Decision rows

Exactly one row per (book, rebalance, name) for every held name and every name with R-rank ≤ 2N, by precedence
`exit` > `exit_pending` > `hold` > `enter` > `not_selected:<infeasible:<rule>|band_full>`.

## 7. Execution

### 7.1 Identity, isolation, states

- Strategy id `ranking-pot-v1`, version `v1`, purpose `demo_trial` (`strategy_manifest.DEMO_TRIAL_STRATEGY_IDS`). One
  placed book; the shadow and controls are computed. One non-terminal declaration per strategy id (partial unique
  index).
- **States** (append-only events, transitions enforced by trigger): `shadow_only` → `executing` ⇄ `halted_loss` /

  look, only while no v1 declaration is active, and only by a supervisor script run from the main checkout; a freeze

  entries (continuous, not one-way).
- **Isolation tests:** pot rows invisible to every `ai_trial_*` evidence, readout and decision query (the shared pool's

- **No evidence writes** to `strategy_results_store`, promotion tables or another strategy's evidence.
- **v1 untouched:** no edit to `ai_trial_policy.POLICY_MODULES` files or `FROZEN_CONSTANTS`; each slice PR pastes
  `scripts/ai_trial_policy_guard.py` output; a shared non-hashed module a slice changes is declared and its v1 path

### 7.2 Loader, ledger, sizing, submission

**Loader:** one query at submission: signal ↔ `enter` row ↔ `decided` rebalance ↔ digest-intact declaration ↔
instrument ↔ strategy id/version ↔ deployment agree; long; state `executing`; target session is today
(`decision_expired`). Every non-evidence gate of `_load_intent` kept with its code, classified like v1's
`PAPER_GATE_MAP` with the parse-both-loaders test.

**Ledger (slots, as the shadow):** N executed slots, each opened at `POT_CAPITAL / N`. An entry's requested ticket is
its slot's cash; exit proceeds return to that slot; losses are never replenished and no slot draws on another (fixed
capital, enforced by the ledger, not by the pool's mode). Free slots fill in ascending slot index by entry order.

**Sizing and submission:** the full `_risk_and_amount` path under the paper allocator lock (every concurrency,
daily-loss, drawdown, halt-feed, reconciliation and authority gate), with `stop_loss_pct = 100 × (ask − SL) / ask` of
the validated levels; durable-before-I/O order write; `_submit_recorded_order`; `_resume_uncertain_submission`; only
`place_demo_strategy_order`. State, declaration and the loss check (§7.4) are re-read under row locks inside the
authority transaction. Capacity may reduce the ticket to the broker open minimum (requested vs actual recorded), never
raise it.

- **Cost cap:** stressed what-if cost ≤ 1.0% of the amount (v1's constant, by construction).
- **Levels:** from the pre-submission ask and the snapshot ATR14, after a split check (the snapshot's last close vs the
  current stored close for the same session; a ratio ≠ 1 refuses `basis_changed`). Asserted: finite,
  `0 < SL < ask < TP`, `1 ≤ (ask − SL)/ATR14 ≤ 4`, `TP − ask ≥ 1.5 (ask − SL)` (`protective_levels_invalid`).
- **Slots:** a name already held or in flight is refused (`pot_name_in_flight`); more than N refuses (`pot_slots_full`).
- **Order:** exits first; entries size from capacity reconciled at their own submission. One attempt per entry per
  rebalance; a refusal leaves the slot in cash to the next rebalance.
- **Fills:** partial fills, slippage beyond the levels and post-halt fills follow the existing reconciliation and
  protection paths; slice 5 lists each and tests the pot's case.

**The loader, the slot ledger and the executor (slice 5b, by construction; Codex ckpt-1's 43 items disposed in the
slice PR).** `ranking_pot_intent.py` (loader, slot ledger) and `ranking_pot_executor.py` (sizing, submission, the job
body) are policy-hashed; the shared paper machinery they call (`_risk_and_amount`, `_submit_recorded_order`, the
reconciliation) is not, as for v1. `sql/450` adds two append-only tables: `ranking_pot_activations` (one row per
declaration: `POT_CAPITAL`; written by 5c's activation script, so until 5c every entry refuses `pot_capital_missing`)
and `ranking_pot_exec_submissions` (one per lifecycle: slot, slot wealth, requested ticket, amount, ask, quote time,
ATR14, the SL/TP sent; r3-109). Its trigger requires the trade to fund the lifecycle's own signal, in its slot, for
exactly that amount, and to have been created by the inserting transaction, so the row commits with its authority
before any broker I/O or not at all. The broker-accepted levels and their repair are 5c's half of r3-108.
- **Job** `ranking_pot_execute`, hourly at :05 on the paper execution lane (as `ai_trial_execute`; :05 keeps clear of
  its 15:00 fire); acts only while the regular session is open and from 15:00 UTC, and the executor itself raises
  before 15:00. Due = lifecycles with no funding decision whose target session is today (New York), in entry order
  (attempt, lifecycle id: 5a inserts them in entry order in one transaction). The halt feed is refreshed first; an
  exception on one entry is contained, counted and retried by the next fire (an exception is not a refusal).
  Exits are 5c's. Free-slot entries do not wait for exits: their ticket is their own slot's wealth, and the
  account-level capacity terms are read at their own submission (§7.2 "Order").
- **Loader**, refusing in this order: signal ↔ lifecycle (the exec tables hold only the executed book, r3-110) ↔ its
  `enter` row ↔ the attempt `decided` ↔ strategy id and version (`pot_identity_mismatch`); the declaration digest,
  the ticket and the decided snapshot each re-hash to their stored sha256 (`pot_not_intact`, r3-111); the signal's
  `ranking_pot_policy`, the attempt's and the declaration's policy hash and the running `RANKING_POT_POLICY_HASH`
  all equal (`pot_policy_drift`, r3-112); fill bar = target session = today (`decision_expired` /
  `decision_not_yet_due`); state `executing` (`pot_not_executing`); no AI-trial declaration `active` (`v1_active`);
  `ranking_pot_look.look_pending` clear at the target session (`look_pending`, r3-89; a harm wind-down already
  leaves `executing`, r3-35); the activation row; then the **slot** (below), before any market gate, so a stale
  quote can never consume the one attempt of an entry that would have deferred. Then every non-evidence gate of the
  paper `_load_intent`, same codes, same order, with `PAPER_GATE_MAP` classifying each of its codes (a test parses
  both sources, as v1's): scan → `replaced:decision_expired`; the forecast stop bound →
  `replaced:pot_stop_exceeds_policy` (the sent stop's percentage ≤ the policy `stop_loss_pct`, as v1 keeps it);
  missing barriers → `replaced:protective_levels_invalid`; evidence gates `dropped`. Capital mode `fixed`, currency
  USD. The executor wraps it in v1's sequence: trading enabled, uncertain resume, reconciliation overdue, loader,
  risk snapshot, `_risk_and_amount`, eligibility and minimum, what-if cost, cost cap, authority.
- **Slot ledger** (r3-114–118). Slot wealth W = `POT_CAPITAL / N` + Σ `trade_events.realized_pnl_usd` (eToro
  `netProfit`, "the net profit of the trade"; one row per partial close, unique per position and close time, summed
  as `strategy_monitoring.load_owned_pnl` does) over the slot's `closed` lifecycles; `failed`, `refused` and
  `expired` add 0. A `closed` lifecycle is booked when it owns at least one position, every one is released and has
  close events, and every `netProfit` is present and finite. Only booked P&L enters, so unreceived proceeds are never
  spent (r3-114); a reduced ticket or partial fill leaves its residual in W (r3-116); broker cash not yet settled is
  bounded by `_capacities`' cash term, not by W. Open-position accruals (`totalFees`: overnight fees and dividends)
  reach W inside that lifecycle's `netProfit` when it closes, never another slot's (r3-117); so does any cost the
  broker debits outside the amount (≤ 1% by the cost cap), so W can be overdrawn by at most that and only into its
  own slot (r3-115). Whether `netProfit` already nets `fees_usd` is undocumented, so a slot holding a close event
  with `fees_usd` ≠ 0 or NULL refuses `pot_slot_fees_ambiguous` (persisted; the slot stays in cash every month until
  the semantics are documented — on dev 11 close events, 0 with `fees_usd` ≠ 0, so it is unpriced today: the #2602
  precedent). Requested ticket = W rounded down to the cent; capacity may reduce it, never raise it. W ≤ 0 after
  rounding → `pot_slot_depleted` (the slot is retired); 0 < W < the broker open minimum → the existing
  `below_broker_minimum` (r3-118).
- **Slots and names.** Counted over lifecycles that **commit capital** (an `allocated` decision whose trade is not
  `closed` or `failed`); an entry never counts against itself and an undecided queued entry commits nothing. Another
  committed held lifecycle in the slot (a stamped exit not yet closed, or a late fill reviving a released one) →
  the deferral `pot_slot_not_released`; another committed held lifecycle of the name → `pot_name_in_flight`; N
  committed lifecycles → `pot_slots_full`.
- **Deferrals.** `pot_slot_not_released` and `pot_slot_ledger_incomplete` (a `closed` lifecycle in the slot not yet
  booked) write nothing: the lifecycle stays `entry_pending`, a later fire that session retries, and after the
  session 5a's classification reads `expired`. Every other refusal is persisted (`_persist_rejection`, outside any
  authority transaction, under the allocator lock), so each entry has one attempt per rebalance (r3-119). An
  uncertain submission is resolved with its own request id by the existing reconciliation, never resubmitted as a
  new attempt; a crash after the authority commits leaves a durable order the same reconciliation owns.
- **Levels and basis.** `basis_changed` unless `ranking_pot.basis_unchanged(snapshot close, current price_daily close
  of the snapshot's last session)` and no `price_series_break` / unsuperseded `price_adjustments` dated after that
  session and on or before today (r3-53, r3-121, r3-122). Levels = `ranking_pot.planned_levels(ask, snapshot ATR14)`
  (exact 3 ATR / 2R, r3-123), rounded down to the cent (slice 5c-ii-c; was 6 dp), then `validate_levels` on the rates SENT
  (`protective_levels_invalid`); the sizing stop is the sent SL's percentage, rounded up (a wider stop sizes
  smaller), computed before sizing.
- **Cost cap:** stressed what-if cost ≤ 1.0% of the amount, by multiplication (`pot_cost_cap`).
- **Authority transaction** (r3-113), READ COMMITTED (the job connection), under the allocator lock that serialises
  the pot with the paper and trial paths: the declaration row `FOR SHARE` (an in-flight state event holds it `FOR NO
  KEY UPDATE`), then state `executing`; `ai_trial_declarations` in SHARE mode and its rows `FOR SHARE`, as
  `sql/445`'s `executing` trigger locks them, then `v1_active`; `look_pending`; then the slot ledger and the slot /
  name checks re-read, and W must equal the W sized from (else the deferral: a booking that landed in between is
  retried, never submitted on the stale figure). Then the funding decision, trade, order, preflight and submission
  row commit together, before `_submit_recorded_order`. 5c adds the §7.4 loss check to this transaction; until 5c
  no state can be `executing`.
- **Residuals** (stated, not removed). The reconciliation does not take the allocator lock, so a predecessor's trade
  can move between the authority's read and its commit; and a late fill reviving a released predecessor AFTER its
  replacement is funded puts two held lifecycles in one slot, which 5a's reader refuses loudly at the next
  rebalance (fail closed; a supervisor matter). Market facts (quote, halt feed, close, policy rows) are read at
  load, seconds before the authority, as on the paper and trial paths.
- **Fills** (r3-120): partial, slipped, post-halt and late fills keep the existing order reconciliation; 5a's
  classification reads the trade (a late fill reopens a `failed` lifecycle as held).
- **Where it runs** (r3-130): the jobs daemon in the main checkout; from a linked worktree the broker-mutation guard
  refuses before I/O, as for v1.

### 7.4 Exits

- **SL/TP** broker-held from the fill. Slice 5 verifies, not assumes, that missing or removed levels are repaired for
  pot trades and that a pending protection edit cannot block a due re-rank exit (both fixes are trial-legs-only today).
- **Re-rank / ineligibility / wind-down exit:** the rebalance stamps an immutable `pot_exit_session` (one per lifecycle);
  the manager closes from the first cycle ≥ 15:00 UTC on or after it, trigger `rerank_exit`, retrying every cycle;
  uncertain closes resolve through the existing close-outcome path.
- **No age exit:** the pot deployment's `max_position_age` is NULL.
- **Exits are never blocked by an entry gate** (settled EXIT rule).
- **Loss check:** executed realised + unrealised net P&L (broker marks via the #3540 bridge, fees and dividends
  included) ≤ −20% of `POT_CAPITAL` → `halted_loss`. The entry path recomputes it under the lock; open or uncertain
  pot exposure without a reconciled mark is charged its stop bound, and a data defect defers the entry
  (`pot_loss_check_unavailable`) — revised by slice 5c-ii-a, below. The halt stops
  entries and does not liquidate. **Nothing bounds the pot's loss at a fixed figure:** per-position stops can gap,
  the halt only stops new risk, and the pool's own mandate limits (`max_portfolio_drawdown_pct`, daily loss) act on
  the whole engine book. The shadow carries no capital and needs no loss check.

**The exits, wind-down stamps and `completed` writer (slice 5c-i, by construction).** Slice 5c is split: **5c-i**
the exits below; **5c-ii** the loss check, the activation script and precheck, and the broker-accepted levels
(r3-108's second half). `ranking_pot_exits.py` is policy-hashed; the position manager it plugs into is shared and is
not (§8's stated residual).
- **Protection.** A pot trade is a signal-arm paper trade (funding → paper deployment → `allocated` preflight →
  execution policy, all written by 5b's authority), so the 5-minute paper cycle's dispatcher selects it and the
  manager repairs a missing SL (or one below the sent SL) and a TP other than the sent TP (`_exit_intent`'s signal
  arm), counted by the #3284 repair streak, which alerts. v1's O10 "close an unrepaired leg and halt" is v1's rule and
  is not adopted (§7.4 states none for the pot): repeated repair refusal leaves an alerting, possibly unprotected
  position (residual, as for every signal-arm trade). A test drives a pot trade with a removed SL through the manager
  and asserts the repair edit.
- **Close.** The manager links a trade to the pot by its `ranking_pot_exec_submissions` row (`is_ranking_pot`, its
  own flag, never `is_demo_trial` and never inferred from a NULL); `sql/450`'s trigger binds that row's trade to its
  lifecycle's own signal and slot, and the stamp is keyed by the lifecycle. Due = `ranking_pot_exits.pot_exit_due`:
  the cycle's instant ≥ 15:00 UTC on `exit_session`; it stays due, so every later cycle retries (dispatch is the
  existing rotating batch, so "first cycle" means the first cycle that selects the position). A due exit is checked
  before the gap repair and the ratchet and also bypasses the missing-open-time hold, and closes with trigger
  `rerank_exit` (`sql/451` adds it to the operation trigger CHECK, drift-guarded as `sql/436`). An earlier close
  still `reconcile_required` without a broker witness blocks a second request (`pot_close_outstanding`, v1's
  predicate; resolved by the #2979 witness path). A close the broker does not allow now (`broker_close_not_allowed`,
  e.g. a halted name) falls through to the protection repair in the same cycle, so an untradable position is still
  repaired; the close is retried next cycle. A pending accepted-but-unlanded edit (`broker_edit_pending`) yields to a
  due exit: it is terminalised `reconcile_required` / `superseded_by_pot_exit` (never `rejected`: the broker may
  still apply it) and the close proceeds. Neither the pot's state nor the kill switch blocks the close (settled EXIT
  rule; halts stop entries only). No age exit: the pot deployment's `strategy_position_manager_policies` row carries
  `max_position_age_seconds` NULL (5c-ii's activation writes it).
- **Wind-down stamps.** In `winding_down`, every lifecycle with an `allocated` funding decision and no stamp —
  whatever its trade's status, including no trade yet — gets one sourced from the declaration's first `winding_down`
  event: `exit_session` = `ranking_pot_step.wind_down_session(event.at)` (W, the same W the books step, so the
  executed and simulated books leave on one session), reason `wind_down:<wind_down_reason>`; insert `ON CONFLICT DO
  NOTHING` (first writer wins, r3-66). A rebalance stamp is never later than W: a rebalance decides only in an
  executed state, after its last session's close, targeting the next session, and the wind-down event commits after
  it (the SHARE lock), so the event's New York date is ≥ that last session and W ≥ the target. An undecided lifecycle
  needs none: the loader and the authority refuse `pot_not_executing` under the declaration row lock, so it ends
  `refused` or `expired`; an authority committed before the event still submits, and its lifecycle is stamped and
  closes at W. The step job (one instance, its lane) stamps at the start of every fire — before the no-snapshot
  return, the looks and the drift check — and again after its looks, so a harm event written this fire is stamped
  this fire, and one written by a fire that later raised is stamped by the next fire's start.
- **`completed` (r3-63, r3-64).** Run by the step job after its looks and steps — the only writer of steps and looks,
  so no look can become due between — and also before its no-snapshot return. One READ COMMITTED transaction:
  stamps first; the state is `winding_down`; the executed book is flat, read from the raw facts rather than the
  classification: no lifecycle undecided and not yet past its target session; no `allocated` lifecycle whose trade is
  absent or not `closed` / `failed`; no `rejected` lifecycle with a trade (a contradiction raises); no active
  `strategy_position_ownership` of a pot trade. Pending entries drain by the existing reconciliation (the paper
  cycle's backlog), not by this writer. When a decided snapshot exists, `sql/448`'s fence (K + 1 checkpoints, none
  holding, the first wind-down applied by a step) is read first, so an unmet fence is a quiet "not yet". Then the
  engine `completed` event. `sql/451` adds a second BEFORE INSERT trigger refusing `→ completed` while a pot trade is
  not `closed` / `failed` or holds active ownership, so no other writer can complete a non-flat executed book. A
  declaration with no decided snapshot completes at once; one that ran the shadow completes after the step applies W.
  Slot proceeds need not be booked first (no entry follows). Residual: a `failed` trade revived by a fill after
  `completed` is outside the declaration; the reconciliation still owns the position and the manager still closes it
  (its stamp exists).

**The loss check (slice 5c-ii-a, by construction; r3-69; Codex ckpt-1's 43 items disposed in the slice PR).**
5c-ii is split again: **a** the loss check (this paragraph), **b** the activation script and precheck, **c** the
broker-accepted levels (r3-108). `ranking_pot_loss.py` is policy-hashed.
- **Marks.** The broker's own per-position `unrealizedPnL` from a LIVE account snapshot
  (`get_account_risk_snapshot().direct_positions`, the rows the #3540 bridge stores daily as
  `broker_account_position_marks`), keyed by the broker position id of the pot trade's ownership rows. The entry path
  reuses the snapshot it sized from (seconds old, like every market fact read at load, §7.2 "Residuals"). The account
  currency must be the documented USD, and the per-position rows must be exactly as many as the direct positions the
  per-instrument rows count (`direct_long_positions + direct_short_positions`; mirrors and pending orders sit in
  `amount`, never in the counts), else the snapshot is unusable.
- **Net P&L**, over every pot trade of the declaration (its `ranking_pot_exec_submissions` row; a funded pot trade
  without one is a defect), per position: Σ its close events' `netProfit`, plus its mark when the snapshot carries
  it (whatever the ownership status: a position the broker still marks is still exposure). Fees are charged
  ADVERSELY because inclusion in `netProfit` / `unrealizedPnL` is undocumented (#3540 memo): − |`fees_usd`| per
  close (sign undocumented), − max(`totalFees`, 0) per mark (the portal documents a negative `totalFees` as a
  refund). Both are no-ops at 0, every stored value today.
- **Reconciled in units, else BOUNDED.** A position counts as exact only when closes + the mark's units = its single
  open event's units, or — before the open event is ingested — the mark is not `is_partially_altered` and no close
  sits beside it; unmarked, only when its closes equal the open units (an over-close, the ingest's own partial-close
  model violation, is a defect).
  Anything else — no ownership row yet (submitted, uncertain, filled and not yet reconciled), an `active` position
  absent from the snapshot (closed at the broker, close not yet ingested), a missing final close, a stale mark beside
  an ingested close — adds its trade's **stop bound** = `amount × ((ask − stop_loss_rate)/ask + POT_COST_CAP_PCT/100)`
  (its submission row, rounded up to the cent) as a loss, and an unreconciled mark then counts only when negative.
  A `failed` trade with no ownership row adds 0. ⚠ This REVISES §7.4's "stale or incomplete marks … refuse the
  entry": an entry submitted this fire has no ownership row until the reconciliation sees its fill, so a refusal would
  let a 25-entry rebalance place about one entry per hourly fire and expire the rest. Residuals, stated: a gap
  through the stop, slippage past the ask, a stop the broker does not hold (5c-ii-c records the held levels), or
  a late fill reviving a `failed` trade before reconciliation can exceed the bound until the mark lands; the bound on
  never-filled orders can halt early: with every slot pending it totals at most their amounts × (`stop_loss_pct` + 1) / 100,
  since the loader refuses a sent stop wider than the policy's `stop_loss_pct` (`pot_stop_exceeds_policy`).
- **Unavailable** (`pot_loss_check_unavailable`) on a data defect only: a NULL or non-finite figure, a duplicated
  mark or a position owned by two pot trades, a short mark, an over-close, the snapshot's currency or count, the
  funded-without-submission check. It is a **deferral** (nothing written, retried by the next fire), because a snapshot defect can heal within
  the session; a persisting one expires the entry, as the slot deferrals do.
- **Breach** = net ≤ −20% × `POT_CAPITAL` (`ranking_pot_activations`), inclusive.
- **Entry path.** `_authority_refusal` evaluates it after the state and `v1_active` checks, inside the authority
  transaction (allocator lock + declaration row `FOR SHARE`). The reconciliation does not take the allocator lock, so
  an ownership row or close event can land between read and commit (§7.2's stated residual). A breach refuses
  `pot_loss_limit` (persisted); after the authority transaction commits, `halt_on_loss` writes `executing →
  halted_loss` (actor `engine`) in its own transaction: declaration row `FOR NO KEY UPDATE` first (the trigger's own
  lock, so no upgrade from the authority's `FOR SHARE`), state re-read, the check RECOMPUTED under that lock, so a
  stale breach never halts a supervisor resumption that came in between, and nothing written unless still
  `executing` and still breached. Lock order allocator → declaration row, as the authority. An authority committed
  before the halt still submits (and `_resume_uncertain_submission` completes it with its own request id); the halt
  stops new authorities, never liquidates and never blocks an exit.
- **Periodic evaluator (r3-69).** Every `ranking_pot_execute` fire while the regular session is open — before
  15:00 UTC too, entries or not — evaluates each `executing` declaration against ONE live snapshot through
  `halt_on_loss`; no broker call when none is `executing`. Outcomes go to the job note (`loss[<id>]=ok | halted |
  unavailable | activation_missing | snapshot_failed | error`); an exception is rolled back and does not stop the
  others. A crash between an entry's refusal and its halt is caught by the next fire. Outside the session the state
  is not re-evaluated (entries happen only inside it); between fires it lags by up to an hour.

**The broker-held levels (slice 5c-ii-c, by construction; r3-108; Codex ckpt-1's 28 items disposed in the slice
PR).** Three recorded values, one per question:
- **Sent** — `ranking_pot_exec_submissions.stop_loss_rate` / `take_profit_rate`, durable before I/O (5b). A level
  the broker refuses at submission is the order's own rejection (`orders.raw_payload_json`); a repair is a
  `strategy_position_operations` row (desired SL/TP, `applied` / `rejected` / `reconcile_required`, the broker
  response). Both exist; this slice adds neither.
- **Held** — new append-only `ranking_pot_exec_level_observations` (`sql/453`): per (pot trade, broker position),
  the four protection fields of the exact-position `get_portfolio` row the position manager read — `stopLossRate`,
  `takeProfitRate` (unrounded `NUMERIC`, NULL when absent) and `isNoStopLoss`, `isNoTakeProfit` as parsed (an
  absent flag parses as "no level", the manager's own fail-safe reading). **Change-only**: a row is written only
  when the four values are DISTINCT FROM the pair's latest row (latest = highest id), so an unchanged cycle writes
  nothing (the `strategy_position_operations` low-cardinality rule). A trigger binds the pair to a
  `strategy_position_ownership` row of a trade that has a submission row, and refuses UPDATE / DELETE. The writer
  serialises its compare-and-insert per position with its own transaction-scoped advisory lock, whatever the
  caller holds (unserialised, an uncommitted change could be overtaken by a later observation of the old value,
  losing the transition: Codex ckpt-3).
  `observed_at` is the cycle's instant (taken before the read; ordering uses the id).
- **Where it is written.** In `manage_owned_position`, for a pot trade, right after the exact position is read and
  before any exit or repair decision. Every edit of ours is created by a cycle that has passed that point first, so
  a position's first row precedes every repair this system sends: it is the first held level observed, which is
  the level accepted at the fill unless the broker or a hand edit changed it in between (stated). A cycle that
  returns earlier (a resumed operation) observes nothing; the first later cycle that reaches the read records what
  is held then. Residuals, stated: a change and its reversal between two reads is invisible; a position closed
  before any cycle reached it has no row (no row = never observed); the log records changes, not liveness, so its
  latest row is not proof of current protection. The writer `ranking_pot_held_levels.record_held_levels` is a
  policy-hashed leaf module (the manager imports it, as it does `ranking_pot_exit_rule`, so it imports nothing of
  the pot's); its call site is in the shared manager (§8's residual) and a test drives a pot trade through
  `manage_owned_position` and asserts the row. **Not a gate:** nothing reads it to decide (slice 7 reads it for the
  ticket), and a failure to write is contained — rolled back, logged, and the cycle's protection and exit
  continue, because a recorder must never block a repair or a close (settled EXIT rule).
- **Rounding.** The sent levels are rounded DOWN to the cent (`ranking_pot.RATE_QUANTUM = 0.01`), replacing 6 dp.
  By construction, not from a published broker rule (none found): the manager's pot arm compares exactly (a flag
  set, a stop below the sent SL, or a TP other than the sent TP is a gap), so a level the broker stores at a
  coarser precision than sent would re-derive the same edit every cycle, which `_prior_same_edit` refuses,
  accruing a #3284 repair-refusal streak on a protected position (the hazard `core_exit_levels` names for its own
  cent quantum). eToro's precision is per instrument (`InstrumentMetadataSlim.precision` / `aboveDollarPrecision`,
  `openapi_v1.375.0`; served only by `/api/v2/watchlists`, not ingested) and its quotes are not cent-only (dev
  `quotes`, 2026-10-02: 15 of 1,740 equity asks sub-cent, e.g. MSFT 517.1301), so what it does with a 6-dp rate is
  unmeasured; a cent rate is representable at any precision ≥ 2, and the only measured round-trip is cents (the
  three active core SPY.RTH positions: `broker_positions` holds their applied repair levels exactly). Down, both: a
  wider stop (the sizing stop and the loss check's stop bound both read the SENT stop) and a nearer target, then
  `validate_levels` on the rates sent. Flooring changes each rate by < 1¢, so it can newly refuse
  (`protective_levels_invalid`) only when SL floors to 0 (`3·ATR14 > ask − 0.01`) or ATR14 < 1/60 $ (a sufficient
  bound, not an exact classifier: below it the cent can break `TP − ask ≥ 1.5 (ask − SL)` or the 4-ATR stop cap).
  Measured on the S₀ stand-in (latest `v1.5-balanced` run, last close ≥ $3, 14-session mean true range; the
  per-entry `validate_levels` stays the authority): 0 and 15 of 3,142, the 15 all SPACs pinned near trust value.
  A held level short of the sent one is visible in the observations; a gap re-derived every cycle alerts through
  the streak. No 6-dp submission exists to migrate (`ranking_pot_exec_submissions` is empty on dev; nothing can be
  `executing` before activation, `sql/452`).
- **Not changed:** the loss check (it reads marks and the sent stop, not held levels); the paper signal arm's 6-dp
  levels (shared, not the pot's; the same precision exposure applies to it — residual, noted on the PR).

## 9. Measurement and verdict

### 9.1 The books and the simulator

The **shadow** (real order) and **K controls** (reassigned order) are computed **online**: after each completed
session a job advances every book one session from that day's stored bars and appends the result. The appended ledger
is authoritative; a later provider rewrite does not change it (and is visible as a discrepancy). Rules:

- **Entry:** at the target session's close × (1 + h), h = the snapshot half-spread fraction. Levels from that entry
  price and the snapshot ATR14: SL = entry − 3·ATR14, TP = entry + 6·ATR14; if SL ≤ 0 the entry is refused in the book
  (`protective_levels_invalid`, counted). Protective checks start the next session.
- **Protective exit**, each session after entry, opening gaps first: open ≤ SL → open; open ≥ TP → open; else
  low ≤ SL → SL (also when high ≥ TP the same session, by construction); else high ≥ TP → TP. Fill × (1 − h_exit).
- **Rank / ineligibility / wind-down exit:** the target session's close × (1 − h_exit), after that session's
  protective check.
- **h_exit:** the half-spread from the latest snapshot holding a valid quote for the name, else its entry h.
- **Bars:** a bar with a missing or non-finite field, high < low, or open/close outside [low, high] counts as missing.
  A missing bar marks at the last close. On the 5th consecutive missing session the position exits at the last close ×
  (1 − h_exit), recognised that day (no backdating). Untradability is known only at a snapshot and exits as
  `ineligible`. Cash takeovers appear as missing bars; spinoff value is lost in every book alike (residual).
- **Splits:** each session's step checks the stored close of the previous session against the ledger's; a ratio ≠ 1
  rescales the position's units and levels by it and records the event.
- **Slots and NAV:** N slots at 1/N; a slot invests its whole cash on entry and holds the proceeds at exit; cash earns
  0; free slots fill in ascending index by entry order; a slot at ≤ 0 is retired. NAV = Σ slots at closes, starting at
  1.0 before the first entry.
- **Statistic T:** the mean, over every open position-session in the window, of that position's net return that
  session (entry and exit costs in their own session). Equal weight per position-session. This is the spike rules'
  per-trade expectancy made duration-consistent; CAGR and Sharpe stay out of the decision. What T does not see
  (compounding, a depleted slot's small size, idle cash) is covered by §9.3 condition 2, which is on NAV wealth, and
  by the occupancy minimum.
- **Price-only, all books:** no dividend table covers the universe; dividends are omitted everywhere. Selected and
  random names need not have equal yields, so price-only outperformance is not proof of economic outperformance; the
  yield gap is reported where `dividend_events` covers the names (§9.4).
- **Costs:** half-spreads only. Broker fees beyond the spread are omitted in every book and for SPY (residual; the
  executed book's what-if costs show their size).
- **What the shadow is not:** it does not apply broker minimums, cost caps or capacity. §9.3 condition 5 is what
  stops a shadow-only pass being read as an executable one.

**The step job (slice 6a, by construction; Codex ckpt-1 dispositions in the slice PR).** `ranking_pot_step.py`,
policy-hashed, hourly at :10 on the `db` lane.
- **When (r3-40).** Session S is due from 09:00 UTC on the calendar day after S (the §4 (*) bar wait). One step
  transaction (REPEATABLE READ, `ranking_pot_state_events` SHARE-locked before its first query, then the declaration
  row) reads everything once: each name's bar for S through the masked reader (`price_masked_bars.load_masked_bars`,
  the snapshot's basis), the reference closes, SPY's bar. The values that transaction reads are the values stepped
  and stored; a bar absent or masked then is missing for S for good. A stepped session is never re-stepped. The masked
  reader returns no bar beyond an instrument's quarantine coverage, so until `price_quarantine_refresh` (orchestrated
  after the candle refresh; it finished 01:55–19:31 UTC over 2026-09-24 → 10-01) covers S, the gate refuses and the
  next fire retries.
- **Gate (r3-30..32).** Bar validity is the simulator's `valid_bar` (all four prices finite and > 0, range-consistent)
  everywhere. The population is every name held or pending in any of the K + 1 books (r3-31) plus, when a decision is
  applied at S and no wind-down falls on S, F_t (a superset of the names entering in some book). The gate passes when
  SPY's bar is valid and ≥ 95% of the population has a valid bar (inclusive, as §4 step 2; an empty population
  passes). A failed gate writes a refusal row (session, counts) and nothing else, and is retried at the next fire. A
  session still unstepped once 10 later NYSE sessions have completed is stepped WITHOUT the gate (`forced`, recorded),
  so a permanent outage cannot stall the books: missing bars then mark at the last close and the 5-session exit runs.
  Sessions are stepped in order and never skipped.
- **Decisions (§4 (**)).** Before S's step, if a `decided` row targets S, every book's ledger is at its snapshot's
  `last_session` (asserted) and the snapshot's §5 decision is applied to every book. The first decided snapshot
  creates the K + 1 empty books at its `last_session`. Control k ranks by π_k (§9.2's seed: declaration sha, first
  decided snapshot sha). `recently_exited` is the book's lifecycles closed at sessions stepped since the previous
  applied rebalance. Fences: a decided row whose target session is already behind the ledger raises; the database
  refuses a step for S that omits a decided row targeting S, and a decided row for a session already stepped. A
  decision for S commits by 12:00 UTC on S (§4 (*)); S is stepped from 09:00 UTC the next day.
- **Wind-down (§5.1 rule 3).** W = the first NYSE session after the first `winding_down` event's New York date. At
  W's step, after any decision targeting W, every book stamps each unstamped position for W and drops its pending
  entries; the step row records the event id. W is always after every session that can be stepped when the event
  commits (stepping S needs 09:00 UTC on S + 1 day), so a W already behind the ledger and not applied raises. After
  the event no rebalance is decided (`sql/446`), so no book is repopulated.
- **Exactly once, atomically (r3-42).** The one transaction covers decision application, wind-down, every book's
  step, the checkpoint check and writes, and the step row; a refusal leaves the books untouched. The step row's key is
  (declaration, session); each checkpoint advances only from the previous session; the policy hash is checked before
  every step (r3-92) and a mismatch records a `policy_drift` refusal and steps nothing.
- **What is stored (r3-43).** One append-only row per stepped session holds:
  - the consumed inputs (each population name's bar for S, every (name, reference session, close) the split check
    read, missing ones included, and SPY's bar), as canonical JSON with its sha256;
  - the shadow's full step: records, closed lifecycles, refusals, rescales, NAV, and the endpoint valuation (the
    session's records with every still-open position charged h_exit, and the charged NAV), plus its §5.2 rows at a
    rebalance;
  - per control, that session's record count, Σ net return, the same Σ with still-open positions charged, NAV,
    charged NAV, positions held after the step, closes, missing-bar exits, refusals and rescales; at a rebalance also
    its entries, exits, unfilled slots, occupied slots and missing-donor count;
  - the digest of every book's checkpoint after the step.

  Any session can then serve as a look endpoint without the checkpoint: T at endpoint E = (Σ over stepped sessions
  before E of the session sums, then E's charged sum, added in session order under the simulator's context) / Σ
  record counts. Each session sum adds that session's records in the simulator's order. Occupancy = mean over stepped
  sessions of positions held after the step / N. The per-book checkpoint (one mutable row per book) is a cache. The
  declaration, the frozen code (policy hash), the decided snapshots in order, the seed, the wind-down event and the
  steps' inputs reproduce it. It is checked against the previous step's digest before every step.

### 9.2 Controls: the order-reassignment null

**Assumption (stated, not designed in).** Under H₀, given every name's own-fact path (which fixes R_t and F_t in every
book) and every name's subsequent price path, which name's score **order** is attached to which name is exchangeable
across S₀. This is stronger than "scores do not predict returns": scores are partly functions of own past prices, so
some reassigned combinations could not arise from the scorer; and cross-sectional clusters are realigned at random.
The test is therefore valid for the policy-level claim "the real assignment beats random assignment", and §1's reading
of a rejection is the only one allowed.

**Construction.** Control k is a uniform random bijection π_k of S₀. At each rebalance, R_t (the same set as every
book) is ordered by the real score of π_k(i) in that run, descending; names whose donor has no finite positive score
that run sort after all others, by `instrument_id`. F-rank is the induced order on F_t. Rules §5.1 apply unchanged.
Score persistence follows the donor's, so turnover is similar to the real book's but not equal (own-fact exits,
stops and slot occupancy differ); §9.4 reports both books' turnover.

**Missing donors (measured residual).** Every R member has a valid own score, but its donor may not: then it sorts
last, a treatment the real book never applies. The rebalance records, per control, how many R members had no valid
donor score; the readout reports the median and maximum share, so the size of this asymmetry is visible.

**Draw.** π_k = a Fisher–Yates shuffle of S₀ ordered by `instrument_id`; each step's index is drawn by rejection
sampling over `sha256(seed ‖ k ‖ j ‖ c)`, exactly as `ranking_pot_sim.draw_bijection` fixes it (r3-6, r3-7). **seed** = sha256 of the declaration sha **and the first
rebalance's snapshot sha** (the snapshot excludes every control-derived field, so the seed is not circular). That
snapshot is published once, fenced, under the declaration; a refused first rebalance publishes nothing and its retry
draws on that retry's data, which nobody chooses. The only way to obtain a different seed is a new declaration, which
the register charges (§8). The randomness assumption (sha256 output behaves as uniform) is explicit. K = 9,999.

**p-values** (Phipson & Smyth, 2010). With T_obs and T_k finite: `p_up = (1 + #{T_k ≥ T_obs}) / (K + 1)`,
`p_down = (1 + #{T_k ≤ T_obs}) / (K + 1)`. A control with no position-session or a non-finite T counts toward **both**
tails (against any claim). A non-finite or undefined T_obs makes the look `unevaluable`.

### 9.3 Looks, bar, states (frozen)

- **Look endpoints** are calendar-fixed: the close of the first NYSE session on or after the 12- and 24-month
  anniversaries of the first rebalance's target session. Cumulative windows. Every book's ledger is valued at that
  close with open positions charged h_exit (as SPY is). A look is computed once its endpoint session has been
  stepped; if the endpoint session could not pass the §9.1 step gate for 10 sessions (it is stepped `forced`), the
  look is `unevaluable`. A rebalance whose target session falls after an endpoint refuses `look_pending` until the look is
  stored. **One authoritative result per look**, append-only; a later correction is a separate row with a reason and
  never replaces the verdict.
- **Minimum evidence:** a look with fewer than 2N closed-or-marked shadow lifecycles, or mean shadow slot occupancy
  below 0.5, is `unevaluable`.
- **Pass, all of:** (1) `p_up ≤ 0.0125` (§8: v1 is m = 1 and spends 0.05 · 2^−1 = 0.025, split over two looks); (2) the shadow's NAV return ≥
  SPY's from the first rebalance's target-session close to the endpoint, SPY charged its snapshot half-spread on entry
  and at the endpoint, price-only on both sides, permanently; (3) the shadow's maximum peak-to-trough NAV decline on
  daily closes from 1.0 ≤ 1.25 × max(SPY's same statistic, 0.05) (floor by construction); (4) breadth guard: the
  median over **names** of each name's summed lifecycle net log-return in the shadow > 0, open lifecycles marked at
  the endpoint with h_exit (one value per name, so repeated wins in three names cannot carry it); (5) execution: the
  executed book was `executing` for ≥ 6 months of the window with ≥ 2N lifecycles. Without (5) the result is reported
  "shadow pass, execution unproven", which is not a pass.
- **Harm:** `p_down ≤ 0.025` at a look (a stopping rule, not an efficacy claim: up to 0.05 over two looks, stated) →
  `winding_down` reason `harm`, effective at the next session (§5.1 rule 3). Harm is relative; the executed book's
  absolute loss is §7.4, and nothing in this spec bounds it at a fixed figure.
- **Invalidation:** a look result found to rest on a confirmed data, code or accounting error is marked `invalidated`
  with the evidence (append-only); an invalidated pass is not a pass. Recomputation is allowed only for the
  documented error and is stored as a new result citing it.
- **Outcomes:** 12-month pass → reported on #2437 as the argument for a small live allocation; continues unchanged;
  confers no authority. 12-month non-pass or unevaluable → continue. 24 months, any outcome → `winding_down`:
  every book exits all positions at the next session, then `completed` when the executed book is flat. A 24-month
  non-pass or unevaluable is "not demonstrated" on #2437; any ETF alternative is argued there, authorising nothing.
- **SPY total return** is reported beside condition 2 if slice 6 finds a reproducible distribution series
  (`I_t = I_{t−1}(close_t + D_t)/close_{t−1}`, ex-date reinvestment, gross of withholding; `SELECT count(*) FROM
  dividend_events WHERE instrument_id = 3000` → 0 today). It never enters the bar.

**The looks (slice 6b, by construction; Codex ckpt-1's 64 items disposed in the slice PR).** `ranking_pot_look.py`,
policy-hashed, run by the step job. Writes `ranking_pot_looks` (`sql/448`). All arithmetic is `Decimal` under
`ranking_pot_sim.CTX`; every threshold comparison is exact (`Fraction`), and p-values are stored as `"p/q"`.
- **Endpoints.** T₀ = the first decided snapshot's target session (by `attempt_id`, the step job's order). A_m = T₀'s
  date with its year advanced by m/12; a date that does not exist (29 February only) becomes 1 March. E_m = the first
  NYSE session ≥ A_m under `market_calendar` (policy-hashed). The result stores T₀, A_m and E_m.
- **When (r3-92, r3-33).** At the start of every step-job fire and after every committed step, the job computes, in
  ascending m, each look whose E_m has been stepped and which has no `result` row: its own REPEATABLE READ
  transaction under the step's lock order, after the policy-hash check (a mismatch computes nothing and does not
  raise, so the next due step records its own `policy_drift` refusal; the fire fails under drift whether or not a
  step was due — that refusal and failed run are the record). A look reads only append-only rows: exactly the
  contiguous step rows T₀ … E_m (one per NYSE session, checked), the decided snapshots and the state events; never a
  checkpoint. No look is computed when a wind-down was applied at a session < E_m (the books were liquidated before
  the window closed); its absence is the record, and no rebalance can follow a wind-down. Any computation error
  (a malformed row, a non-positive lifecycle value) raises; nothing is written and the next fire retries. Residual
  (r3-33): while the step job itself is down no look is computed; `look_pending` makes the stall visible monthly.
- **T (§9.1, §9.2).** Per book, T = (Σ over sessions s < E of the stored plain session sum — controls' `sum_return`,
  the shadow's `session_sum(records)` — then E's charged sum — controls' `sum_return_charged`, the shadow's
  `session_sum(records_charged)` — added in session order) / Σ record counts over s ≤ E. This session-sum
  construction is authoritative for every book (not `t_statistic`'s flat sum), so equal ledgers give equal T. Every
  row's control arrays must have exactly K entries (the declaration's `k_controls`), in book order. A book with no
  record has no T; a non-finite or undefined T_obs makes the look unevaluable.
- **Lifecycles.** Keyed by the shadow's lifecycle number (unique per book). invested = the start value of its
  entry-session record; a closed lifecycle's stored `invested` must equal it. Terminal value = its stored proceeds when
  closed at a session ≤ E, else its E record's charged end value. Count = every lifecycle with a record ≤ E (closed ≤ E
  or open at E). Occupancy = the mean over the stepped sessions T₀ … E of the shadow's `held` / N, exact.
- **Unevaluable**, any of (every one that holds is recorded): `endpoint_forced`; `t_obs_undefined`;
  `lifecycles_below_minimum` (< 2N); `occupancy_below_minimum` (< 1/2); `spy_unavailable` (an invalid stored SPY bar
  at T₀). Conditions are still computed where their operands exist; a condition whose operands do not is stored as
  `null`, never `false`.
- **Paths (r3-27, r3-28, r3-29).** Shadow: 1.0 (the ledger before T₀), each session s < E's `nav`, E's
  `nav_charged`. SPY: unit capital buys a fractional share at T₀'s stored SPY close × (1 + h₀), h₀ = the first decided
  snapshot's SPY half-spread; the path is 1.0, then close_s / (close_T₀ × (1 + h₀)) for T₀ ≤ s < E, then close_E × (1 −
  h_E) / (close_T₀ × (1 + h₀)), h_E = the SPY half-spread of the latest decided snapshot with target session ≤ E (as
  of, r3-44, r3-25). Every decided snapshot carries a valid SPY quote (§4 step 2); a reader that finds none raises.
  Closes are the step rows' stored SPY bars, read through the masked raw-basis reader the step uses, price-only. Only a
  `forced` step can store an invalid SPY bar; it marks at the last valid close. The forced and SPY-invalid session
  counts are stored (§9.3 makes only a forced endpoint unevaluable; nothing new is gated on them). Residual: a SPY
  split in the window is not detected; it is a confirmed data error, handled by invalidation. Both endpoint charges
  are a valuation (r3-28): the 12-month charged point is not on the 24-month path.
- **Condition 2:** shadow path at E ≥ SPY path at E. **Condition 3:** a path's maximum drawdown = max over t of 1 −
  p_t / max_{u ≤ t} p_u over the whole path (the initial 1.0 and the charged endpoint included, r3-29); shadow ≤ 5/4 ×
  max(SPY, 1/20).
- **Condition 4:** per lifecycle ln(terminal / invested) (both > 0, else raise: fills are always > 0), summed per name
  in ascending lifecycle order; the names are those with ≥ 1 shadow lifecycle in the window; the median over them (the
  mean of the two middle values when the count is even) must be > 0; no names → `null`. The distinct-name count is
  stored.
- **Condition 5:** total elapsed time in `executing` within the New York calendar days T₀ … E (00:00 on T₀ to 00:00
  on the day after E, aware timestamps), from the state events in `event_id` order, carry-in clipped at the window
  start, negative intervals clipped to 0, ≥ half the mean Gregorian year (365.2425 / 2 days: the time is a sum of
  intervals, not a calendar span, so "6 months" is fixed as half a year); and ≥ 2N executed-book lifecycles. The
  executed ledger and its lifecycle definition are slice 5's: until it lands the reader returns 0, so (5) fails and a
  look passing 1–4 reads `shadow_pass_execution_unproven`. No declaration can be measured under the stub: the freeze
  refuses until `BUILD_COMPLETE`, which slice 7 sets after slice 5.
- **Verdict:** `unevaluable` when any reason holds; else `pass` (1–5), `shadow_pass_execution_unproven` (1–4 without
  5) or `not_passed`. The row stores T_obs, p_up, p_down, each condition's operands and outcome, the counts, the reasons
  and the policy hash.
- **Harm (§9.3):** evaluated whenever the p-values are defined, unevaluable or not: `p_down ≤` the declaration's
  frozen `harm_alpha` (1/40). The permutation p-value is exact under H₀ at any sample size, so the stated stopping
  bound holds; the minimum-evidence rules guard the efficacy claim, not the stop.
- **State.** Each fire first reconciles, then after each stored look again: in a READ COMMITTED transaction that
  reads the state and then INSERTs (the state writer's order, `sql/445`: ROW EXCLUSIVE on the events table, then the
  trigger's declaration row lock — never the reverse), a harm look among the stored results writes the engine event
  `winding_down` / `harm`; else a stored 24-month result writes `winding_down` / `completed_window`. Nothing is
  written when the trial is already `winding_down` or `completed`; the look row still carries `harm`. A stale
  transition or a lost race raises and the next fire retries. W follows §9.1 from the event's commit date, so an
  outage delays the stop; the event time records by how much.
- **`look_pending` (r3-35, r3-89).** In the rebalance job after the not-due, window and state exits and before the
  bar wait and scoring: once a decided snapshot exists, the earliest look m with E_m before the target session and no
  `result` row refuses `look_pending` (detail: m, E_m); so does a stored look whose wind-down event is not yet written.
  Both conditions only ever clear (append-only rows, a frozen endpoint rule), so a check taken before scoring stays
  true. A rebalance targeting E_m itself is not refused: its entries fall inside the window and every book takes them
  alike. Slice 5 obligations: the executor re-reads the state under the declaration row lock at every submission and
  resume (a harm wind-down then stops intents already published), and the `completed` writer computes due looks first.
- **One authoritative result (`sql/448`).** Append-only rows of kind `result` (the engine's; one per declaration and
  look), `invalidation` (cites a result, carries the evidence) or `recomputation` (cites its invalidation). v1 writes

- **Activation fence (r3-34).** The state trigger refuses `→ executing` — activation and resumption alike, §7.1 —

  snapshot there is no fence.
- **Completion fence (r3-63).** The state trigger refuses `→ completed` when a decided snapshot exists unless exactly
