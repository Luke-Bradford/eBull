# #2327: an SEC-native issuer-CUSIP bridge from Schedule 13D/G

Status: spec, 2026-10-20. Rung: corpus change (identifier mapping that moves 13F / N-PORT
observations and the #3841 PIT market-cap anchors). Slice 2 of the #3908 plan; slice 1 was
#3926 (`33360af2`).

## Problem

`external_identifiers` binds a CUSIP to an instrument by three routes today:

1. `cusip_universe_backfill` fuzzy-matches the latest 13F Official List's issuer name against
   `instruments.company_name` (threshold 0.92, `sec_13f_securities_list.backfill_cusip_coverage`);
2. the legacy resolver fuzzy-matches filer-reported names (`cusip_resolver`);
3. OpenFIGI CUSIP → ticker, the approved fallback (settled decision 2026-05-22).

None of them uses a structured CIK. #3908 found large, heavily held names unmapped (VICI, RIG,
WTM, SUI.US, FR.US, ADC, EPRT, NE, SHO, ORA.US): their 13F holdings sit in
`unresolved_13f_cusips` and their PIT market cap refuses `no_left_anchor`. The issue's own
complaint also stands: XOM, TSLA, BAC and KO are still bound by OpenFIGI alone, so the fallback
carries names SEC publishes.

The corpus already holds an SEC-native pair: every Schedule 13D/G row in `blockholder_filings`
carries the issuer's CIK and the CUSIP of the class it reports on. This spec binds those CUSIPs.

## Source rule

- **What the 13D/G CUSIP is.** Rule 13d-101 (Schedule 13D) cover page: "(Title of Class of
  Securities)" and "(CUSIP Number)"; Item 1: "State the title of the class of equity securities
  to which this statement relates and the name … of the issuer". Rule 13d-102 (13G) has the same
  cover. Since 2024-12-18 both are EDGAR XML (`sec-edgar.md` §2.4, §7.7): issuer CIK in
  `<issuerCik>`, CUSIP in `<issuerCusips>/<issuerCusipNumber>`
  (`sec_13dg._issuer_identity_from_root`, #1628). The CIK is an EDGAR entity key; the CUSIP is
  filer-typed. In our corpus 45 of the 7,490 values have the wrong shape (ISINs, 10-character
  values, "MULTIPLES", "INAPPLICABLE") and 56 more fail the check digit.
- **CIK = entity, CUSIP = security** (settled 2026-05-10, #1102). A CIK alone never chooses a
  share class; #1628's resolver binds by CIK only when the CIK maps to exactly one instrument.
- **Authority order** (settled 2026-05-22; `sec-edgar.md` §3.2): SEC sources are the CUSIP
  bridge, OpenFIGI the fallback. Both inputs to the bridge are SEC.
- **The 13(f) security universe** is SEC's Official List of Section 13(f) Securities
  (`sec-edgar.md` §3.2, "CUSIP → CIK bridge"). Its rows carry no structured security-type field
  (checked: CUSIP, `*` added-since-last flag, issuer name, description, status), so the existing
  description classifiers decide share rows: `_is_common_share`, and `_is_put_call` for option
  classes under Form 13F Special Instruction 10 (#2353). `_is_common_share` refuses any
  description containing a `CALL` token, which drops the seven products #2353 found (structured
  notes and covered-call ETFs); none is an operating company's equity.
- **CUSIP structure** (CUSIP Global Services): characters 1–6 are the issuer number, 7–8 the
  issue number, 9 the check digit: modulus-10 "double-add-double" over characters 1–8, `0-9` at
  face value, `A-Z` = 10–35, `*` = 36, `@` = 37, `#` = 38, every second value doubled, digits
  summed. Verified on AAPL `037833100`, GOOGL `02079K305`, GOOG `02079K107`, VICI `925652109`,
  RIG `H8817H100`, WTM `G9618E107` (pass) and the AAPL CALL pseudo-CUSIP `037833900` (fails).
  One issuer's classes share the issuer number (GOOGL / GOOG `02079K`, BRK `084670`); R5b uses
  that.
- **List window.** Fixed start 2024Q4: the quarter of the 13D/G XML mandate (2024-12-18) and of
  today's 13F retention floor (`thirteen_f_retention_cutoff`, 2024-12-31). It grows by one list
  per quarter and does not roll, so evidence of a past dual listing is never aged out.

**No source rule exists** for telling a CUSIP succession (reverse split, redomicile) from two
concurrently listed classes. R5 is an ambiguity heuristic chosen here, with its known misses in
Limits, and the rule version freezes it.

## Rule v1 (`CUSIP_BRIDGE_RULE_VERSION = "13dg-bridge-v1"`)

Gates in order; the first refusal decides. Candidate `X`, issuer CIK `C`:

- **R1.** `X` fully matches `[0-9A-Z*@#]{8}[0-9]` and its check digit holds.
- **R2.** Every 13D/G row naming `X` names the same `C` (after zero-padding to 10 digits).
- **R3.** `C` maps to exactly one instrument `I` (`siblings_for_issuer_cik`); none or several
  refuses (#1628's never-guess rule).
- **R4.** `X` is a non-deleted share row (`status <> 'D'`, `_is_common_share`, not
  `_is_put_call`) on at least one window list.
- **R6.** `X` has a `cusip` row, under any provider, for an instrument other than `I`: refuse.
  The bridge never overwrites.
- **R5a.** Take `I`'s CUSIP set: every candidate for `I` that passed R1–R4, plus every existing
  `cusip` row of `I`. If any two are co-listed as share rows on two or more window lists, or are
  both on the latest list, refuse every candidate of `I`.
- **R5b.** If a share row that shares `X`'s issuer number and is not in `I`'s CUSIP set is
  co-listed with `X` on two or more lists or on the latest list, refuse `X`: it is a class of
  the same issuer that we do not hold.
- **R5c.** If `I` has an existing CUSIP other than `X` and none of them shares `X`'s issuer
  number, refuse `X`. A new issuer number on a mapped instrument is a redomicile or a filer
  error, and nothing we hold tells them apart.
- Otherwise: already a `sec` row for `I` is a no-op; an `openfigi` row only (the only other
  provider holding CUSIPs) is a **confirm**, which adds the `sec` row; no row is a **bind**.

**Duplicate lists.** SEC serves `13flist2025q3-txt.txt` (Last-Modified 2026-09-03; the legacy
`13flist2025q3.txt` is 404) byte-identical to `13flist2025q1.txt` (`7393a3557aff…`). Every other
pair of window lists differs. Nothing in the file says which quarter it is: SEC re-uploaded the
2025 lists in September 2026 (2025Q1 and Q2 also carry Last-Modified 2026-09-04), and the `*`
flags do not separate them (of the 5,721 flagged rows, 5,664 are on 2024Q4's list and 5,611 on
2025Q2's). So **both** quarters are gaps, and the available window today is 2024Q4, 2025Q2,
2025Q4 and 2026Q1–Q3. A gap counts **against** binding: for R5a and R5b, a gap counts as a
co-listing for any pair co-listed on the nearest available list before or after it. Against a
gap-blind count of 974 binds, this costs 205; the lost binds are mostly microcap reverse-split
CUSIPs (ASNS, APVO, ACET), which OpenFIGI mostly cannot answer.

## Construction

1. **Schema (one migration).** `cusip_bridge_bindings (external_identifier_id BIGINT PRIMARY
   KEY REFERENCES external_identifiers, cusip TEXT NOT NULL, instrument_id BIGINT NOT NULL,
   issuer_cik TEXT NOT NULL, outcome TEXT NOT NULL CHECK (outcome IN ('bind', 'confirm')),
   rule_version TEXT NOT NULL, accessions TEXT[] NOT NULL, list_quarters TEXT[] NOT NULL,
   list_sha256 TEXT[] NOT NULL, job_run_id BIGINT NOT NULL, bound_at TIMESTAMPTZ NOT NULL
   DEFAULT now())`. A row exists only for an `external_identifiers` row this bridge inserted;
   it carries what is needed to replay the decision. No `ON DELETE CASCADE`: rollback reads it
   first. The mapping stays under `provider = 'sec'`, so no reader's provider allow-list changes
   (prevention log #2213).
2. **Lists.** `ensure_window_lists(conn, fetch, today)` in `sec_13f_securities_list`: fetch and
   `_store_raw_list` each window quarter missing from `sec_reference_documents` (today five), raw
   store before parse (prevention log #914). An unpublished latest quarter follows
   `fetch_latest_published_list`'s grace rule. A stored list counts as available only if it
   parses to at least 10,000 rows and its SHA-256 differs from every other quarter's; otherwise
   it is a gap. The bridge does not run when the latest window quarter is a gap.
3. **Service.** `app/services/cusip_bridge_13dg.py`. A pure `decide(inputs) -> outcomes` holds
   every gate; `bind_13dg_cusips(conn, job_run_id)` reads its inputs, CUSIPs normalised by
   `strip().upper()` and CIKs zero-padded, accessions counted after normalising. Per write, in a
   savepoint: `pg_advisory_xact_lock` on the CUSIP; re-read `X`'s `cusip` rows and `C`'s
   siblings and re-apply R3 and R6; `INSERT (instrument_id, provider, identifier_type,
   identifier_value, is_primary) VALUES (I, 'sec', 'cusip', X, FALSE) ON CONFLICT (provider,
   identifier_type, identifier_value) WHERE NOT (provider = 'sec' AND identifier_type = 'cik')
   DO NOTHING RETURNING external_identifier_id` (the settled partial-index predicate); write the
   provenance row only when a row came back. When none came back, re-probe the `sec` row: same
   instrument counts as already mapped, a different instrument as a conflict (the existing
   helper's pattern). The OpenFIGI promotion in `cusip_resolver` and the fuzzy insert take the
   same advisory lock around their inserts. R2's and R4's inputs (filings, lists) do not change
   inside a run; R5's existing-CUSIP input is re-read under the lock with R6.
4. **Job.** `cusip_universe_backfill` runs `ensure_window_lists`, `bind_13dg_cusips`, then the
   existing fuzzy backfill and `sweep_resolvable_unresolved_cusips`. A bridge refusal is an
   abstention: the other routes behave as before. The fuzzy pass selects instruments without a
   `sec` CUSIP, so it skips what the bridge mapped. Each run also re-evaluates the existing
   bridge rows against the current inputs and reports, never deletes, any that would now refuse;
   each reported row is adjudicated by hand like the R6 population. The job note carries
   outcome counts, gaps, conflicts and that report.
5. **Tests.** Pure `decide`: R1 including a trailing newline and a non-ASCII digit; each gate on
   constructed inputs, including a succession (co-listed once, old CUSIP off the latest list →
   bind), a dual class (twice → R5a), both on the latest list (→ R5a), an unheld same-issuer
   class (→ R5b), a new issuer number (→ R5c), a gap next to a single co-listing (→ R5a), and a
   duplicate payload. One DB test for insert, provenance, conflict, race count and re-read.

## Deploy, history backfill and acceptance

Mapping alone fixes only future ingests: the bulk drains resolve CUSIPs at ingest
(`load_bulk_cusip_map`), and `sweep_bulk_cusips_resolved_via_extid` only re-labels
`unresolved_13f_cusips`. The bind CUSIPs hold today, as `[rows, observation_count]`: bulk 13F
`openfigi_unknown` [664, 1,946,342] and `openfigi_no_instrument` [28, 199,130]; bulk N-PORT
[510, 245,173] and [28, 42,943]; legacy pending [767, 920,365]. `observation_count` counts
sightings, so these bound the recovery rather than predict it. `blockholder_filings` needs
nothing: R3 admits only single-instrument CIKs, which #1628 already resolves, and 0 of its
NULL-instrument rows carry a bind CUSIP.

Order on dev, as one attended window. `cusip_universe_backfill` has `catch_up_on_boot`, so
steps 1–3 precede the deploy. No identifier- or observation-writing job runs from step 1 to step
6 (checked on `job_runs` at each step; the dev schedule is paused for the window). Each step
passes, or the sequence stops and the spec is amended.

1. **Inventory:** download the missing `form13f_01mar2025-31may2025.zip` (period 2024-12-31,
   inside the floor) with the directory-safe `download_bulk_archives` call
   (`2026-09-16-bulk-cache-lifecycle.md` §4.1), so every replayed archive is on disk.
2. **A/B of the bridge** in a rolled-back `REPEATABLE READ` transaction (`SELECT 1` first, since
   an idle `conn.transaction()` commits): rows gained = binds + confirms, none lost, no
   pre-existing CUSIP's instrument changes in `load_bulk_cusip_map`; outcomes equal this table
   or each difference is traced to an input that changed (new filings, CIK rows, CUSIP rows).
   OpenFIGI on any bind not in `q8.json`: zero "US, other ticker". A wrong bind amends the rule;
   it does not get an exception. The A/B's bind set fixes the recipients for steps 3–6.
3. **Before-image and raw double-report check.** Save the full rows of both observation tables
   for every recipient instrument, and an `md5` of each other instrument's rows ordered by
   their unique key. In every archive of the replay inventory, list the accessions (13F) and
   fund reports (N-PORT, keyed by series) that hold two CUSIPs mapping to one recipient. Each is
   read: lots of one security summed by the drain are correct; one position reported under both
   an old and a new CUSIP is a double count and fails the step.
4. Deploy; the bridge runs; its outcome set equals step 2's, CUSIP by CUSIP.
5. **History:** `sec_13f_ingest_from_dataset` over the replay inventory, then
   `sec_nport_ingest_from_dataset` over its inventory, then `cusip_resolver_post_bulk_sweep` and
   `sweep_resolvable_unresolved_cusips`. Phase-C ingest deletes each archive afterwards (the
   existing lifecycle; rollback does not need them).
6. **Observation A/B** against step 3: every non-recipient instrument's `md5` is unchanged;
   every recipient's step-3 rows are still present and unchanged except where the new rows of
   the same `(filer, period, exposure)` key re-aggregate them, each such row listed; rows gained
   are reported per source and recipient; the bind CUSIPs' unresolved rows are re-labelled. The
   smoke panel AAPL, GME, MSFT, JPM and HD is unchanged.
7. `market_cap_pit_rebuild` (#3841). It publishes a new build; the previous build stays for
   comparison.
8. **Cross-source and live:** VICI's institutional ownership share for the latest complete 13F
   quarter against marketbeat's figure on the same day, within 10 percentage points (the filer
   sets differ); a miss sends the sequence to rollback; `/instruments/VICI/ownership-
   rollup` and `/instruments/RIG/ownership-rollup` show institutional holders; the new PIT
   build publishes VICI.
9. **#3908 decomposition re-run** on the new build, posted on #3908. Expectation from today: 264
   of the 696 `no_left_anchor` instruments gain a bind, 200 of them among the 279 with no CUSIP.
   It reports; it does not gate.

## Rollback

1. Pause the dev schedule; set the rule version to disabled so a resumed job does not rebind.
2. In one transaction: copy the run's `cusip_bridge_bindings` rows to a rollback manifest table,
   delete those provenance rows, then delete the `external_identifiers` rows they name. A
   confirm whose `openfigi` row has since gone is left in place and listed.
3. **Binds:** replace each recipient's rows in both observation tables with the step-3
   before-image. Rows that arrived after step 3 for those instruments re-arrive on their next
   ingest; the list of them is kept. Refresh `ownership_institutions_current` for the
   recipients, re-label their CUSIPs' `unresolved_13f_cusips` rows back to pending, and re-run
   `market_cap_pit_rebuild`.
4. Confirms move no observation.

## Not in scope

- **The 68 disputed bindings** (R6): re-binding moves observations off the holding instrument,
  a separate corpus change with each CUSIP adjudicated.
- **ISIN salvage** (`US50101L1061` carries CUSIP `50101L106`): R1 refuses it today.
- **Multi-instrument CIKs** (R3: 108 CUSIPs, including GOOGL and GOOG): need a class
  discriminator we do not hold; they stay on OpenFIGI and on #2327 after this slice.
- **OpenFIGI fallback defects** from #3908 (REIT filter, CINS, `.US` match); the bridge covers
  the named cases.

## Limits

- The bridge infers a security from an entity plus list evidence. It does not prove a class.
  The evidence is SEC's share-row listing (R4), the absence of a concurrent sibling class (R5),
  and an OpenFIGI ticker match on 235 binds with no contradiction. 492 binds have no external
  check. That is a judgement, and it is #1628's: that resolver already attributes every
  13D/G row by single-instrument CIK.
- **R5 misses** a second class we do not hold with a different issuer number (an ADR and its
  foreign ordinary, ASND `04351P101` / `K08588103`; R5a catches it when both are ours), and two
  classes co-listed on exactly one list with one gone from the latest list. A class listed only
  in a gap quarter is invisible.
- **R5 over-refuses** in the safe direction: a succession inside the latest quarter waits a
  quarter, the two gap quarters cost 205 binds, and R5a refuses 54 CUSIPs OpenFIGI agrees with.
- Old CUSIPs carry 13F holdings in the units of their own period, the same as any pre-split
  holding reported under an unchanged CUSIP.
- Coverage comes only from issuers with a post-2024-12-18 13D/G.

## Checkpoint record

Codex checkpoint 1 ran three rounds (the cap), `-m gpt-6-astra`; prompts and outputs are
`var/autonomy/2327/ckpt1_r{1,2,3}.{prompt,out}`.

- **Round 1** (32 findings) changed the rule: R5's threshold was recalibrated on the operational
  window, R5b and R6-before-R5 were added, the additional-CUSIP count was corrected, and every
  candidate got an OpenFIGI check. That check found CNSP's wrong bind, which produced R5c.
- **Round 2** (38 findings) changed the evidence and the procedure: 245 (now 235) ticker matches
  were stated rather than 315 "validated"; all 70 no-US binds were read; the misdated list became
  a pessimistic gap; the window stopped rolling; the provenance became replayable; the deploy got
  a before-image.
- **Round 3** (27 findings, verdict NOT SOUND) named as blocking: class identity inferred from
  entity identity (B1–B3); the duplicate-list rule differing between spec and script (B4, fixed:
  both quarters are now gaps in both); later contradictory evidence (B14, B16: re-read under a
  shared lock, conflicts classified, invalidated bridge rows reported and adjudicated); writer
  boundary, replay completeness and observation comparison (B19–B23: attended window, inventory
  first, per-instrument hashes and before-image); and rollback (B25–B27: FK-safe order, restore
  from the before-image).

**Residual disagreement.** Codex's B1–B3 ask for affirmative class evidence for every bind. No
SEC source we hold supplies it for the 492 binds OpenFIGI cannot answer, which include the CINS
names (RIG, WTM) that motivate the ticket. This spec binds on the SEC gates, records the residual
in Limits, and relies on the before-image rollback if acceptance finds a wrong class.
